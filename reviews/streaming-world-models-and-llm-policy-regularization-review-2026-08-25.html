ReWorld: An Interactive World Model with Long-Horizon Memory

Tier 2 · Research Paper arXiv 2026-08-24 World models · Streaming video · Long-horizon memory · Attention routing · LoRA distillation

Overview

  • Zhifei Chen, Luozhou Wang, Guibao Shen, Dongyu Yan, Shuai Yang, Tianshuo Xu, Yihua Du, Wei Wang, Tianyi Gui, Lianghua Huang and Yingcong Chen (HKUST(GZ) and ATH, Alibaba; project done during an internship at Alibaba) release ReWorld, an action-controllable streaming world model built on the Wan2.2-TI2V-5B video diffusion backbone. arXiv:2608.23565v1 [cs.AI], submitted 2026-08-24, HF Daily 2026-08-25. Code at zhifeichen097/ReWorld, project page at zhifeichen097.github.io/ReWorld.
  • The framing: an interactive world model must simultaneously follow the user's actions, remember the places it has already shown, and keep streaming in real time — and the three requirements pull against each other. Control wants a short attention window (the current scene plus the current command sits inside a short recent context); memory wants an unbounded one (retrieval can only be learned if distant content is visible in the attention window). When the abilities are trained together on shared heads, adding direct action injection lifts every control metric but drops revisit fidelity. At deployment there is a second bind: an unbounded KV cache exhausts device memory before the horizons at which spatial memory is actually tested, so the cache must be bounded — and any bounded cache is a sparse, non-contiguous history that standard teacher forcing has never trained the backbone to read.

Methodology

  • Named contribution 1 — MRoPE (Memory-RoPE): pose-indexed attention as implicit spatial memory.
    • Problem. Standard RoPE indexes attention by time and space, so a location revisited after a long detour is, positionally, just a distant timestamp — retrieval has to be inferred from content alone, which is exactly the regime where content signals are weakest.
    • Mechanism. Each latent frame f carries a relative camera-to-world pose Pf ∈ SE(3) (anchored to the first frame), collapsed to a 12-D descriptor cf = [vec(Rf); tf]. A zero-initialised MLP maps this descriptor to a phase offset δf that rides on top of RoPE for both queries and keys within the same attention pass: q̃ = RoPE(q)·eiδf(q), k̃ = RoPE(k)·eiδf(k), so ⟨q̃,k̃⟩ ∝ ei(δf(q)−δf(k)) and attention depends on pose difference rather than temporal distance. Zero-initialised SE(3) residuals on values and outputs (ṽ = v + Wv(Pf−1∘v), out = Woy + Wp(Pf∘y)) complete the conditioning.
    • Why it works / why it beats prior. Similar viewpoints are pulled together no matter how far apart in time, so the cache acts as an implicit spatial memory addressable by pose proximity. Unlike two-pass designs (HY-World 1.5, E-PRoPE) that add a separate camera-aware attention pass and either double attention FLOPs or add a reduced-token pass, MRoPE uses pose as a retrieval index in the existing pass: cost is one small MLP plus two linears, and the attention kernel, mask layout, and per-head windows stay untouched — which is what lets the mixed-window / random-routing recipe below plug in without kernel changes. MRoPE alone gives strong revisit memory but imprecise control, which is the gap the next mechanism fills.
  • Named contribution 2 — direct action injection via Plücker ray maps.
    • Problem. Pose-indexed retrieval addresses cached content by pose difference but does not command the next chunk's camera; leaving control to inferred pose is imprecise, especially for out-of-distribution moves.
    • Mechanism. The commanded pose of each latent frame is expanded into a Plücker ray map: every spatial position receives the 6-D coordinates [d, o×d] of its viewing ray under that pose (direction d, camera centre o, expressed in the same first-frame basis as the MRoPE poses). An MLP projects the map to model width and adds token-wise to the patch embeddings at the transformer input. The two channels now split roles cleanly: the ray map tells each token of the current chunk where its camera should look, and MRoPE poses tell attention where every cached token was seen.
    • Why it works / why it beats prior. Direct action injection is the standard control lever in the interactive-world-model literature (HY-World, GameNGen-derived stacks); the twist is that combining it with MRoPE on the same heads makes the action signal crowd out pose-keyed retrieval — control improves, long-horizon memory degrades. The paper's next mechanism is what makes the pairing usable.
  • Named contribution 3 — mixed per-head attention windows with random head routing.
    • Problem. Control and memory need different windows to be learned — control needs the short window it will actually see at deployment, memory can only train under a long window because a model that cannot see the far past has nothing to retrieve from — but a fixed per-head split of "long" and "short" heads is unusable at inference because the full history is gone and every head reads the same bounded cache. A fixed partition trains heads to depend on windows that deployment cannot provide.
    • Mechanism. Every training iteration exposes the backbone to both windows at once. Of H=24 attention heads per block, 18 are local and attend to only the last w=12 latent frames (three chunks); the remaining |G|=6 are global and attend over the full causal history — a 1:3 global-to-local budget. To keep this workable at deployment, the assignment of which heads are global is routed: a fixed pool of |P|=12 random six-head global sets is drawn, and every optimiser step switches to the next set in the pool. Every head thus spends steps in both roles. At inference the training-time per-head split is dropped: all heads attend over the bounded cache.
    • Why it works / why it beats prior. Because a head is local on most steps, the control it learns must be complete within the short window — so retrieval keeps living in whichever heads currently see far, but no head specialises in a long window. The recipe makes a testable prediction: swapping cache-compression policies at inference should leave control error unchanged (verified in Sec. 4.5). This is the axis on which ReWorld improves over unified-attention interactive world models: instead of trying to make one attention window serve both jobs, it trains the model to be indifferent to which heads are picked to see far, so bounded-cache deployment does not disturb action following.
  • Named contribution 4 — landmark consolidation and pose retrieval under a bounded KV budget.
    • Problem. The KV cache grows linearly with the rollout horizon; at 720p an unbounded cache exhausts device memory well before minute-long horizons. Sliding-window caches simply forget; mean-pool compression keeps the whole history at degraded fidelity but blurs recognisable landmarks; retrieval-free static banks do not adapt to what the current pose actually needs.
    • Mechanism. ReWorld separates write from read. On the write side, aged chunks are admitted selectively into a bounded landmark bank M (|M|≤K=30) at full resolution — no pooling, merging, or token-level pruning. Admission uses an odometer rule: a chunk aging out of the recent window is stored only if the camera has travelled at least a stride δ (in median step lengths) since the last stored landmark. Crucially, the rule measures distance travelled — never whether a place is already banked — so a revisit pass is stored just like the first visit; gating against the whole bank would discard exactly the chunk a later revisit needs (paper reports only ~64% far-revisit coverage under that variant). When the bank is full, each admission evicts the member most redundant in pose space (nearest-neighbour minimum), and the first two members are never evicted since the earliest region tends to be revisited across the longest gaps. On the read side, the active set at chunk k is Ck = {1}sink ∪ {k−5,…,k−1}recent ∪ Tkretrieved with |Tk|=6 and |Ck|=B=12; the six landmarks nearest the current camera pose enter as Tk and are read through MRoPE. Device memory stays at O(B) chunks regardless of rollout length; the full bank lives in pinned host memory with landmark transfers overlapping denoising on a separate stream.
    • Why it works / why it beats prior. Consolidation trades coverage for quality: keep few chunks, keep them intact, keep them diverse. The odometer admission rule, redundancy-based eviction, and pose-proximity retrieval together turn the KV cache into a spatial map indexed by camera pose, so long-range revisits address the right chunk directly rather than having to reconstruct scene state from a lossy summary.
  • Named contribution 5 — chunk-drop training for sparse-cache robustness.
    • Problem. The consolidation cache above hands the model a sparse, non-contiguous subset of its history at inference, whereas standard teacher forcing conditions every denoising query on a contiguous, complete causal prefix. The train/test gap manifests as blur and drift the moment chunks are evicted.
    • Mechanism. For a training clip of L=12 chunks, the sink chunk is always kept and five further survivors are drawn at random at every optimiser step, so each step exposes the model to a random half of its history (6 of 12 chunks). The attention mask is restricted accordingly: the query for chunk zk attends only to the clean keys of surviving earlier chunks and its own chunk, and queries are never dropped, so every chunk still receives its denoising loss. The keep-set is resampled independently at every step and broadcast so all data- and sequence-parallel ranks apply an identical mask.
    • Why it works / why it beats prior. The spliced caches produced by the landmark policy are now in-distribution rather than an OOD input the backbone has never seen. Combined with pose-indexed attention (which makes any retrieved chunk still addressable regardless of temporal distance), chunk-drop training is what lets the same set of weights serve both the multi-step training regime and the sparse-cache streaming regime without an inference-time distribution shift.
  • Named contribution 6 — metric-scale-aligned eight-source data engine with palindrome augmentation.
    • Problem. A world model needs a single physical action scale so that the same commanded action moves the camera the same distance in every source — otherwise the model learns a per-source action calibration and generalisation collapses. Estimated poses (VIPE, MegaSaM) are defined only up to scale; engine poses differ in units. On top of that, memory training requires revisit evidence — scenes where the same place is seen twice from the same pose — which normal trajectories rarely provide.
    • Mechanism. Eight sources make up 220,724 pose-annotated clips: two Unreal-Engine renders (UE control 95,895 clips, UE expansion 42,536), three real-world (DL3DV 29,864, RealEstate10K 12,065, Sekai real-walking-hq 14,730), three game (game-roaming across 79 games 18,387, OmniWorld-Game 5,629, Sekai game-walking 1,618). A curation funnel drops clips moving too fast or too slow to align on-screen speed. Per-source translations are then rescaled by a single divisor σs = meds[‖Δt‖] / medUE[‖Δt‖] with the UE anchor medUE[‖Δt‖] = 0.3667, and all sources are unified to camera-to-world matrices in a common camera basis. For memory supervision, with probability 0.2 on the two UE sources the training window is replaced by a palindrome — a random half of the window concatenated with its temporal reverse — injecting explicit revisit evidence that long-horizon spatial memory training needs. Training mixture ends at 63% UE, 26% real, 11% game.
    • Why it works / why it beats prior. UE trajectories are drawn from six planned modes with a control mode that anchors each path at two points of interest and fills the segment with direction-balanced random motion, so backward, strafing and diagonal moves are sampled as evenly as forward — the paper explicitly attributes action-following accuracy as much to this trajectory design as to the model, since forward-biased footage gives little supervision for rarer directions. Palindromes give the retrieval mechanism a supervision signal that ordinary linear trajectories cannot provide.
  • Named contribution 7 — real-time distillation with a plug-in DMD LoRA.
    • Problem. A multi-step diffusion streaming generator is not real time. Full-backbone step distillation would replace the model and risk drifting control off the ray-map path; consistency-model-style distillation is known to introduce artefacts.
    • Mechanism. The multi-step model is the teacher and the student is the same backbone, frozen, plus a rank-128 LoRA on attention and feed-forward layers — the LoRA is the only thing trained (the DMD critic is also a LoRA over the frozen weights). Training follows distribution-matching distillation with self-forcing rollouts: the student streams chunks from its own KV cache, just as at deployment, so distillation needs only text prompts — no video. Prompts are 248K generic long captions extended from VidProM. The action and pose injection path carries no LoRA, so control is untouched by distillation. One backbone thus has two modes: adapter off is the original multi-step model, adapter on streams in real time at 4 denoising steps. The 2.6 GB adapter transfers across base checkpoints, re-distilling in 2k–4k steps.
    • Why it works / why it beats prior. Confining distillation to a LoRA keeps the multi-step operating point intact and localises the deployment latency win to a pluggable component. Because the action/pose path is outside the LoRA, control quality carries over from the multi-step teacher rather than being learned by a small student from scratch. Self-forcing on the student's own KV stream removes the exposure-bias gap that hurts autoregressive video distillation.

Data pipeline

  • Eight-source joint corpus of 220,724 pose-annotated clips, three groups: UE-rendered (control + expansion, produced by an automated UE service across 337 environments with NavMesh-based trajectory planning), real-world (DL3DV, RealEstate10K, Sekai real-walking-hq), game (game-roaming across 79 games, OmniWorld-Game, Sekai game-walking). Each clip is stored as RGB video, per-frame camera trajectory, and text caption; UE control clips additionally carry per-frame action labels.
  • Trajectory design for the UE control set: six planned modes at constant mode-specific speed; the control mode anchors each trajectory at two points of interest and fills the path between them with randomised motion segments so backward, strafing and diagonal motion are sampled as evenly as forward motion — a data-side answer to the direction bias that limits action-following accuracy in real footage.
  • Curation funnel: 110,204 → 95,895 UE control clips (splitting, speed filter, captioning, darkness/wall filter); expansion set 47,726 → 42,536; game-roaming curated from 494.7 hours across 168 games down to 18,387 clips from 79 games.
  • Metric-scale alignment: single divisor per source against the UE anchor at medUE[‖Δt‖] = 0.3667; all sources unified to camera-to-world matrices in a common camera basis.
  • Sampling: 63% UE, 26% real, 11% game at clip level; each dataset access draws a random 189-frame window resampled to 24 fps (≈8s = one training window); palindrome augmentation applied with probability 0.2 on the two UE sources.

Evaluation & Results

  • Setup: two-stage training on Wan2.2-TI2V-5B — 480p (384×640) pre-training then 720p (704×1280) warm-start with interpolated spatial RoPE. Each training window covers L=12 latent chunks with H=24 heads split into |G|=6 global + 18 local (window w=12), cycling through the |P|=12-partition pool. Chunk-drop keeps sink + 5 random survivors. Deployed inference: 4-step DMD-distilled LoRA (rank 128, block size 16, single-rollout student) on EMA weights, CFG scale 1, per-head windows dropped — all heads read the bounded B=12 cache. Landmark bank capped at |M|≤K=30.
  • Three-axis evaluation protocol: (a) camera controllability, (b) long-horizon memory (out-and-back revisit under bounded cache), (c) general video generation quality. Baseline set: six recent interactive world models covering pose-conditioned autoregressive video generators and streaming world-model stacks.
  • Headline numbers from the abstract: best control fidelity of any evaluated system at 11.95° rotation error and the best camera-motion consistency; the best generation quality on the shared video-quality track. On minute-long out-and-back rollouts (64s, 384 latents), the fixed 12-chunk cache regenerates the starting view — at rollout lengths where a sliding window has long evicted the evidence and full-KV attention runs out of memory.
  • Streaming output at 704×1280 (720p) across photorealistic, game-style, and stylised worlds.

Ablations

  • Control–memory decoupling: adding direct action injection on top of MRoPE alone improves every control metric but drops revisit fidelity when both signals share every head — the motivating measurement for the mixed-window routing recipe. Under the mixed-window routing, control error is stable when cache-compression policy is swapped at inference (the paper's stated testable prediction).
  • Training recipe and cache policy: the deployment landmark policy is compared against four alternatives under identical budget B=12 — unbounded full-KV (undeployable upper bound), sliding-window cache with sink (forgetting baseline), mean-pooled compression of aged chunks, and a retrieval-free static bank of six pose-deduplicated landmarks attended in full. The paper reports the landmark-consolidation policy dominates the deployable alternatives on the memory axis while matching them on control error, with far-revisit coverage sensitive to the choice of admission rule (odometer distance vs global gating).
  • MRoPE vs two-pass baselines: the design comparison table sites MRoPE at time+space+pose in one attention pass with a small MLP + two linears extra cost, against HY-World 1.5 (temporal RoPE + separate camera-aware pass, ≈2× attention FLOPs) and E-PRoPE (separate reduced-token camera pass, ~4.5× fewer tokens for the second pass); MRoPE alone yields strong revisit memory but imprecise control, motivating the paired action injection channel.

Beyond the Stability–Exploration Dilemma: Environmental Regularization for LLM Policy Optimization

Tier 2 · Research Paper arXiv 2026-08-24 RL post-training · Policy optimization · KL regularization · GRPO/PPO/REINFORCE

Overview

  • Xianlei Zhou, Xiangdi Meng, Yu He, Tianyu Qi, Shuyan Guan, Xianli Zhang, Jian Zhang, Xin Li, Qika Lin and Jun Liu (Alibaba) release ERPO (Environment-Regularized Policy Optimization), a drop-in replacement for the Policy-KL regularizer in RL post-training pipelines. arXiv:2608.23311v1 [cs.CL], submitted 2026-08-24, accepted to EMNLP 2026 main conference. Code at alibaba/ERPO.
  • The framing: policy optimization for LLMs currently mediates the stability–exploration trade-off through an action-side Policy-KL regularizer, and practitioners are stuck in a double bind — keeping Policy-KL constrains response behaviour and consumes the action-side exploration budget, while dropping it (as several recent GRPO variants do) leaves optimization without an explicit drift control and blows up under high-temperature decoding or long-horizon training. ERPO argues this is the wrong axis: the drift that matters most is not the response distribution's drift, it is the drift of the query distribution induced by the current policy from its pre-RL reference distribution, which under standard PO is unchecked.

Methodology

  • Named contribution 1 — Query-KL (QKL) regularizer.
    • Problem. The Policy-KL term supervises the response side, which is exactly the side one wants to leave free for exploration; but with no regularizer the query distribution the policy actually sees during training drifts away from the pre-RL reference as easy or reward-friendly queries dominate. Long-horizon training and high-temperature decoding are precisely the regimes where this unchecked drift shows up as instability.
    • Mechanism. ERPO adds a Query-KL term that bounds the distance between the current-policy-induced query distribution and a pre-RL reference query distribution. Crucially the QKL gradient flows strictly through the query likelihood: the response score function used by policy-gradient estimators (GRPO/PPO/REINFORCE) does not appear in the QKL term, so QKL exerts no direct gradient pressure on the response distribution.
    • Why it works / why it beats prior. Because the regularization pressure lives on the input side, the response-side exploration budget is preserved — the trade-off the Policy-KL term forces is dissolved rather than balanced. ERPO plugs into GRPO/PPO/REINFORCE pipelines without additional forward passes, so the compute profile is unchanged relative to the KL-free baseline.
  • Named contribution 2 — dataset-static reference-derived per-query weight.
    • Problem. Bounding the query distribution alone is not enough — per-query updates still weight the queries as they arrive under the drifting policy, so easy or reward-friendly queries can dominate every gradient step. What is needed is a per-query weight that says: "under the reference, this query would have been sampled this often, so weight its update accordingly."
    • Mechanism. ERPO computes a per-query weight up front from the reference distribution — static across training, keyed to the dataset — and biases each per-query update toward queries typical under the reference. Because the weight is precomputed and dataset-static, it adds no online overhead.
    • Why it works / why it beats prior. Weighting per query is a distributional correction that per-response methods (importance sampling on responses, off-policy corrections) cannot supply, because the drift being corrected lives at the query level. Making the weight reference-derived and dataset-static removes the estimator's variance and keeps the correction well-defined even under long-horizon training regimes where an online estimate would drift.

Evaluation & Results

  • Benchmarks: six mathematical reasoning benchmarks. Comparison is against the standard GRPO/PPO/REINFORCE stack with the conventional Policy-KL term (kept and dropped variants). Headline outcomes reported in the abstract: ERPO replaces the Policy-KL regularizer while achieving effective control over query distribution drift, delivering stronger accuracy and substantially more stable behaviour under (a) high-temperature decoding and (b) long-horizon training — the two regimes where dropping Policy-KL is known to destabilise policy optimization. Specific per-benchmark numbers are in the paper body.
  • Compute and pipeline compatibility: no additional forward passes vs the KL-free baseline, so the intervention is a drop-in swap at the loss level rather than a new training loop.

Ablations

  • The paper's abstract commits only to the aggregate claims (stronger accuracy, more stable behaviour under high-temperature decoding and long-horizon training); specific ablation numbers isolating the QKL term vs the per-query weight and Policy-KL kept-vs-dropped are in the paper body. The natural axes are: (a) QKL only vs QKL + reference-derived per-query weight, (b) ERPO vs Policy-KL vs no KL under varying decoding temperature, (c) ERPO vs baselines across training horizon length.

Other

  • Positioning: the paper argues that the field's framing of a stability–exploration dilemma is an artifact of the KL being on the wrong side of the objective; environmental (input-side) regularization dissolves the dilemma rather than balancing it, and does so at zero extra forward-pass compute. That framing is what makes the mechanism a drop-in for GRPO/PPO/REINFORCE recipes rather than a competing algorithm.
