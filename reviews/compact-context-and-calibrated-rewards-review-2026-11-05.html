NVIDIA

You don't need long context

Tier 2 · Technical Report (31 pp., 8 figures) arXiv:2611.05306 (cs.AI) 2026-11-03 submitted Compaction · Long-horizon agents · Semantic state · Serving efficiency

Overview

  • Peter Belcak, Saurav Muralidharan, Jindong Jiang, Yonggan Fu, Wonmin Byeon, Hanrong Ye, Ryan Angilly, Ali Taghibakhshi, Shih-Yang Liu, Siru Ouyang, Greg Heinrich, Pavlo Molchanov (NVIDIA, nv-dler / Project Moonshot: Local Frontier Intelligence, research.nvidia.com/labs/lpr/lfi/).
  • The report's one-line thesis (verbatim, abstract): “Later tokens are costlier to generate than earlier tokens. On frontier open weight models, the disparity in cost may rise to as much as 7x. Through frequent compaction, we show across a broad range of long-horizon and long-input tasks that frontier language models sacrifice little to no task accuracy when maintaining short contexts.”
  • Four research questions structure the report: RQ0 — are long contexts necessary at all?; RQ1 — long-horizon tasks without long contexts; RQ2 — long-input tasks without long contexts; RQ3 — can long-horizon tasks be completed with at most one action per context? RQ3 is the strongest reduction, because it eliminates in-context trajectory memory entirely.
  • Two minimal ReAct harnesses: mini-swe-agent (one Bash action per step, for SWE / Terminal workloads) and mini-agent (generalized, for non-SWE benchmarks). Neither tracks a vector memory or a scratchpad across turns; compaction and file-system reads are the only mechanisms for long-range state.
  • Rejected alternatives made explicit in the report: Full-History Accumulation (baseline), Mamba-style neural state-space models (compared conceptually under Section 5.1), vector-memory / scratchpad harnesses (not studied).

Methodology

  • Compaction primitives. The harness owns three settings that control when a conversation ends: a total context limit (hard ceiling), a compaction threshold (when a compaction request fires), and a compaction scope. The report fixes the scope to “entire history since last compaction” and sweeps the (limit, threshold) pair across 48K/36K, 32K/24K, 24K/18K, 16K/12K.
  • End-of-Conversation Compaction (EoCC). The model is run normally until the conversational context crosses the compaction threshold, then is asked once to “produce a bounded, task-relevant compaction of its state.” The compaction is appended to the task prompt in a fresh conversation (same system prompt) and the agent resumes. This is the paper's default long-horizon mode.
  • Single-Action Compaction (SAC). Each conversation performs exactly one environment action, observes its result, updates the semantic state, and is discarded. The next conversation starts cold with the task plus the updated state. SAC is restricted to mini-swe-agent because non-SWE benchmarks need multi-step within-turn tool use.
  • Selective input reading. Long inputs are stored as named files (input01.txt onwards) and read incrementally through standard Bash (sed, awk, head, wc). The report argues this “reduces a long-input workload to a long-horizon workload,” which EoCC then collapses.
  • Serving cost measurement. Two latency/throughput regimes: cloud API (closed-weight), and local serving on a single NVIDIA DGX Spark (128GB unified memory, ~109GB usable, NVFP4 / Q4_K_M / IQ3_XXS weights). Cloud ratios are reported as per-generated-token cost at window 256K vs 16K. Local figures are tokens-per-second against generated-token index.
  • Benchmarks. Long-horizon: SWE-bench Verified (500), SWE-bench Multilingual (300), Terminal-Bench 2.1 (89), FRAMES (824), τ2-bench (184 golden). Long-input: BFCLv3 (200 long-context episodes), LongBench v2 (503), LOONG (1,600), AA-LCR (100), Needle in a Haystack (125-instance grid at 16K–500K), RULER (13 tasks at 256K and 500K), Counting-Stars (192), BABILong (550 at 64K–11M).

Appendix B reports 16K/256K cost ratios of 0.2772, 0.1777, 0.1439 for the three models; rounded mean r = 0.20.

Named contributions & mechanisms

  • End-of-Conversation Compaction (EoCC).
    • Problem. Long-horizon agents accumulate turn history that pushes the context window into the per-token cost tariff region (up to 7× at 256K vs 16K) while adding little to the model's ability to pick the next action. Full-history accumulation pays the 7× tariff from turn 5 onwards on frontier open models.
    • Mechanism. The harness monitors the conversational-context length each turn. When it crosses a configured threshold, one additional model call is issued whose only job is to produce a bounded compaction of the conversation state (plan, next intent, pointers to artifacts, task restatement). The next turn starts a new conversation seeded with the original task plus that compaction string; the old conversation is discarded. The (limit, threshold) pair fully specifies behavior; the model does the compaction with its own policy, no external summarizer.
    • Why. Dropping conversation history at a known boundary is cheaper than retrieval or paging: no retrieval index, no learned memory module, and the model's own output format carries over as the compaction schema. Compared to conversational scratchpad patterns, EoCC never grows a hidden sidecar state; the compaction is the state. Compared to Mamba-style neural state, the state is text, so it survives model swap, inspection, and manual repair.
  • Single-Action Compaction (SAC).
    • Problem. EoCC still spends most of the conversation inside a “long” context before tripping the threshold. If the only state worth keeping fits in a few KB of text, a budget that permits one call per action is an upper bound on how short the context can get; anything less requires state outside the conversation.
    • Mechanism. One action per conversation, one observation, one state update. The agent emits an action, the environment returns its observation, and the agent is immediately asked to rewrite the semantic state; the conversation ends. The next conversation starts cold with the task plus the rewritten state. Live context stays in the 15–37K band for all tested tasks.
    • Why. SAC is the operational equivalent of a state-space model with a visible state. The paper presents it as the baseline for RQ3: if SAC holds, then full-history accumulation is doing something not strictly necessary for the task. Results on Opus 4.5 are within 1–2 points of EoCC-best; GPT 5.6 Sol's degradation under SAC is the one case where the reduction loses measurable ground.
  • Semantic State Space Models (SSSMs).
    • Problem. SAC demonstrates that short, textual semantic state preserves most of the trajectory signal, but it uses a harness to enforce the state boundary. A model post-trained explicitly for this style of inference could skip the harness, but no public model is.
    • Mechanism. An SSSM is a model post-trained to read a natural-language state description, reason internally, take an action, register the outcome, and rewrite the state for the next inference instance. The paper names this concept and sketches its training setup but does not post-train or release such a model. Compared to neural SSMs (Mamba, Hyena), the state is a text artifact rather than a vector, so it can be read, edited, versioned, and used as a checkpoint between model versions.
    • Why. The report frames SSSMs as what the harness-level results suggest: if accuracy survives SAC, then there is “no reason why SSSMs could not match the performance of full-history-accumulating models,” and the serve cost drops by the cost ratios above. It is a proposal, not a measurement; the paper's own experiments stop at the harness level.

Ablations

  • Compaction scope. Appendix A compares full-trace compaction against since-last-compaction compaction; the paper reports that keeping the task restatement, the current intent / next steps, and execution-artifact pointers — and dropping the narrative trace — produces the strongest compactions. Verbatim: “the best compactions are not those that faithfully capture the gist of the agentic trace.”
  • (Limit, threshold) sweep. Best settings differ by benchmark: SWE-bench Verified best at 24K/18K (Opus) and 48K/36K (GPT 5.6 Sol); Terminal-Bench 2.1 best at 32K/24K (Opus). 16K/12K wins on no benchmark; it is the most aggressive setting and degrades consistently.
  • Harness floor. Changing from mini-swe-agent to mini-agent on long-input benchmarks does not change the qualitative RQ2 story; the selective-reading step drives the result.
  • Open-weight results are in Appendix D and extend the headline to the five locally-served open models above; the appendix-level numbers are not in the main-text tables and the Section 3 / Section 4 narrative refers to them only by direction, not value.

Safety & limitations

  • Lossy compaction. Compaction drops information; repeated compaction can drop critical state. The paper gives a “coin-toss” adversarial example that is “guaranteed to eventually fail” under any fixed-budget compaction and proposes a record-keeping harness with selective-reading tools as the mitigation.
  • Repeated work. Compaction can increase total spend by forcing the model to re-derive facts in later conversations that the baseline kept in-context; the headline savings figures account for this.
  • Vendor-reported only. No third-party replication of the closed-weight numbers yet; cloud benchmarks run through API calls at 2026-10 list prices. Open-weight local serve numbers are tied to the specific DGX Spark configuration.
  • SSSMs are a proposal. No weights, no post-training recipe, no eval of an actual SSSM against EoCC or SAC. The report treats Section 5.1 as a design sketch, not a result.

LoCo: Local Preference Learning for Reasoning Compression

Tier 2 · Research Paper arXiv:2611.04814 (cs.AI) 2026-11-03 submitted Reasoning compression · Step-level DPO · Overthink detection

Overview

  • Muyao Yuan, Liyan Xu†, Weizhan Zhang*, Muyan Jiao, Jiangnan Li, Jinchao Zhang, Jie Zhou* (MOEKLINNS, School of Computer Science and Technology, Xi'an Jiaotong University, and WeChat AI, Tencent Inc.; project lead Liyan Xu, corresponding Weizhan Zhang and Jie Zhou).
  • The paper's position is that trajectory-level reasoning compression (Kimi k1.5 Long2Short, O1-Pruner, CoT-Valve, TokenSkip, Step-DPO) all optimize the same objective over the whole chain-of-thought and therefore cannot decide, at any specific step, whether more reasoning helps. LoCo is reframed around that step-local decision.
  • Code and model to be released at github.com/MuyaoYuan/LoCo.

Methodology

  • State representation. A chain-of-thought is split into paragraph-delimited steps s_i. The reasoning state at step i is P_i = prompt(q) ‖ s_0 ‖ … ‖ s_i (Eq. 1). The state is causal: P_i is observable at step i and nothing after.
  • Overthink detection (step-level, from the model's own distribution).
    • Step confidence c_i is the mean of the top-1 next-token probabilities pτmax over the tokens of step s_i (Eqs. 2–4).
    • Step volatility v_i = (c_i − c_{i-1})2 / 4 (Eq. 5): the normalized squared jump in confidence from one step to the next, computed over the minimal window of two.
    • Overthink flag O = { i : c_i ≤ q25(c) ∧ v_i ≥ q75(v) } (Eq. 6): simultaneously low-confidence and high-volatility steps. Percentiles q25, q75 are calibrated once on the model's own traces, not online.
  • Judge re-check. A stronger judge (Qwen3-30B) labels each candidate step as overthink, normal, or final (Eqs. 7–8). Only overthink-labeled candidates are kept; final labels are excluded so the compressor does not cut answer-restating steps.
  • Verified continuations (same prefix, shorter suffix). From each surviving state P_i, sample k = 8 continuations. Keep only continuations that are symbolically correct by math_verify on the final answer, and among those keep the shortest (Eqs. 9–11). The point is retained only if the shortest-verified continuation is strictly shorter than the original.
  • Pair selection. Each surviving (P_i, y+, y-) triple must have savings ≥ δ = 300 tokens, prompt ≤ 6k, continuations ≤ 12k. Retain at most K = 3 pairs per question, choosing the largest-saving ones (Eq. 12).
  • Training. Standard DPO on (P_i, y+, y-) with the same prefix for both branches; log-likelihoods summed over response tokens. Base is DeepSeek-R1-Distill-Qwen-7B, LoRA rank 256, α = 512, dropout 0.05 on q / k / v / o, β = 0.1, lr 1e-5, two epochs, four H20 GPUs.
  • Training data domain. Math-only, generated from the model's own traces. Code is evaluated out-of-distribution.

Named contribution & mechanism

  • LoCo (local preference learning for reasoning compression).
    • Problem. Trajectory-level compression methods (TokenSkip, CoT-Valve, Long2Short, O1-Pruner) condition only on the whole chain-of-thought and the final answer, so the model learns to prefer shorter trajectories overall rather than to decide step-by-step whether more reasoning is still useful. Step-DPO is step-level but requires externally labeled step preferences, which are expensive and tend to select on the writer's rather than the solver's view of “overthinking”.
    • Mechanism. LoCo builds state-conditioned preference pairs with the same prefix P_i but different continuations. The chosen continuation is the shortest symbolically correct sample the model itself generated from P_i; the rejected continuation is the model's own original rest-of-trajectory. DPO over these pairs with β = 0.1 moves the policy toward the shorter branch at that specific state, with the prefix frozen. The overthink states are picked by the intersection of the model's own low confidence (low c_i) and high confidence jump (high v_i), then re-checked by a stronger judge; both filters are needed to avoid cutting answer steps or inflection points.
    • Why. The same-prefix constraint is what makes this a step-local decision: because y+ and y- share P_i, the DPO gradient cannot push the model to be shorter in general; it can only push toward the shorter branch given this prefix. Compared to TokenSqueeze (trajectory-level, -22.5% tokens on AIME24 with -2.08 accuracy), LoCo (-45.4% with +3.34 accuracy) halves tokens and still gains accuracy. The transfer to code with math-only training is the direct consequence: the policy is learning a length-vs-progress decision rule, not a math fact.

Ablations

  • Global vs local pairs. A Global variant uses trajectory-level pairs (not state-conditioned); token savings collapse to 5.2%–15.8% while keeping comparable accuracy. The local, same-prefix constraint is the piece that produces the -45% savings.
  • External teacher continuations. Replacing self-generated chosen continuations with GPT-5.4 continuations (GPT-5.4 Cont.) yields AIME24 52.92, AIME25 39.58 — close to self-generated but slightly worse, consistent with distributional mismatch.
  • Random vs model-selected cut positions. RandCut (random step chosen) lands at AIME24 48.33 (-2.50 vs base). UniCut (uniform-interval cuts) lands at 48.75 (-2.08). The detector's mean relative cut position is 0.57, versus 0.47 (RandCut) and 0.50 (UniCut); the detector is biased toward the second half of the trajectory, where overthinking is more common.

Limitations

  • Base model scope. All results are on DeepSeek-R1-Distill-Qwen-7B. No experiments on larger reasoning models (DeepSeek-R1-full, Kimi K3-reasoner, GLM-5.3).
  • Math-only training. Code transfer is strong empirically, but the paper does not test mixed-domain training (math + code), reasoning-domain transfer (math → theorem-proving, ScienceQA), or the symmetric case (code-only training → math).
  • Verifier dependency. The pipeline needs a symbolic verifier (math_verify) on the final answer to pick shortest-correct continuations. Domains without such verifiers (open-ended writing, multi-turn dialogue) are out of scope.
  • Judge cost. The Qwen3-30B re-check is a non-trivial per-example cost during data construction, though it runs offline and once per training set.

EmoReward: Self-Evolving Reward Calibration for Emotional Video Generation RL

Tier 2 · Research Paper arXiv:2611.06518 (cs.CV) 2026-11-04 submitted Video RL · Reward hacking · GRPO · HunyuanVideo

Overview

  • Mingzhe Zheng, Yue Wu, Jing Tan, Chang Zou, Dengyang Jiang, Zeyue Tian, Xuanhua He, Ryan Xu, Yunyang Ge, Sihui Ji, Yunlong Lin, Kaihang Pan, Hongru Yan, Sixiang Chen, Dianyi Wang, Julian Zhang, Weijie Kong, Changlin Li, Lanqing Guo, Zhao Zhong, Qifeng Chen, Harry Yang (Tencent Hunyuan, per HF organization badge).
  • Companion artifacts: project page emoreward-project.github.io, code repo github.com/Tencent-Hunyuan/EmoReward (code to be released).
  • Target domain: emotional video generation from text, where no symbolic verifier exists for the correctness of a facial micro-expression, a body-motion cue, or a color-grading choice. Base generator is HunyuanVideo 1.5; transfer experiments on SD 3.5 and FLUX.

Methodology

  • Problem framing. GRPO works on verifiable domains (code, math) because an outcome signal is cheap and deterministic. Emotional video has no such verifier: candidate reward primitives (facial-expression classifier, body-motion scorer, text-alignment model, color-mood classifier, aesthetic scorer) are heterogeneous, noisy, and — crucially — context-dependent: a facial-expression classifier is only informative when a face is clearly visible, a body-motion scorer is uninformative in a close-up shot, and a color-mood signal is weak in a monochrome scene. Flat weighted-sum fusion amplifies whichever primitive scores highly on a given rollout, inviting reward hacking.
  • Pipeline shape. Three stages: (1) a plan stage expands the emotion in the prompt into a short list of grounding cues (e.g., “grief, averted gaze, slow head tilt, muted blue tone”) that the evaluation primitives are asked to look for; (2) an act stage generates G rollouts under GRPO; (3) each rollout is scored by every primitive, then gated and fused.
  • Reflective Reward Gating (instance-level). Four gates are applied before fusion: phase gate (only primitives relevant to the current training phase fire), face-confidence gate (face-related primitives are zeroed when face detection confidence is below threshold), conflict gate (primitives with contradictory signals on the same frame are zeroed pairwise), and subtlety gate (primitives firing on micro-cues that fall below a magnitude threshold are suppressed to avoid noise amplification). After gating, remaining primitive weights are renormalized so the active set sums to one.
  • RewardMemory (between-run calibration). After each training run finishes, a RewardMemory pass estimates each primitive's reliability by comparing its predicted score against rollout outcomes within each emotional regime (per-emotion reliability, not per-prompt). It then sets bounded multipliers that recalibrate fusion weights for the next run. The reward models themselves are not updated — only their fusion weights per emotional regime. The point is to let the fusion forget primitives that the data showed to be unreliable for “grief” but keep them for “surprise”.

Evaluation & results

  • Base generator. HunyuanVideo 1.5. The paper reports gains across multiple RL algorithms (DPO, SAGE-GRPO, and vanilla GRPO) when the fusion layer is swapped to EmoReward; magnitudes are not published in the HF abstract.
  • Head-to-head. Compared to other agentic-reward methods under SAGE-GRPO, EmoReward reports superior emotional-fidelity scores while maintaining visual-quality and text-alignment primitives; the table is in the full paper, not the HF abstract.
  • Transfer experiments. The abstract reports transfer to SD 3.5 and FLUX, which indicates the gating + memory layer is backbone-agnostic. Details of which primitives transfer and which do not are in the full paper.
  • Reported gaps. No numeric table reproduced on HF; no comparison against Sora 2, Veo 4, or other closed-weight video generators; no sanity-check metrics against the base HunyuanVideo 1.5 without any reward on emotional axes.

Named contributions & mechanisms

  • Reflective Reward Gating (instance-level).
    • Problem. Weighted-sum reward fusion assigns a non-zero weight to every primitive on every rollout. Primitives that are uninformative on a given rollout (face classifier on a scene with no face) inject high-variance noise that GRPO will optimize against, producing drift toward backgrounds that spuriously trigger the primitive — a classic reward-hacking failure mode.
    • Mechanism. Four gates evaluate each primitive per rollout before fusion: phase, face-confidence, conflict, subtlety. Each gate's output is 0 or 1. Primitives whose gate product is 0 are dropped from the active set; the remaining weights are L1-renormalized. The fused reward is the weighted sum over the renormalized active set. The gates are conditioned on the rollout's own evidence (face-detection confidence, primitive-pair agreement), not on the ground-truth, so the gating is purely reactive and does not leak oracle information.
    • Why. Dropping an uninformative primitive from the active set is stronger than down-weighting it, because down-weighting still lets GRPO exploit a non-zero gradient from that primitive to drive drift; a zero gate removes the gradient entirely. Compared to SAGE-GRPO's agentic self-critique (which answers “how good is this rollout?”), gating answers “which signals should I trust on this rollout?” before fusion, which the paper claims is where the reward hacking actually enters.
  • RewardMemory (between-run, per-regime).
    • Problem. Instance-level gating decides which primitives to trust on a single rollout; it does not update how much to trust a primitive on “grief” across all rollouts. If the facial-expression classifier systematically misreads grief-coded faces as neutral, no rollout-local gate catches that pattern.
    • Mechanism. After a run, RewardMemory groups rollouts by emotional regime, computes a per-primitive reliability score inside each regime (agreement between primitive score and composite outcome), and sets a bounded multiplier (clipped to a safe range) to recalibrate fusion weights for the next run. The underlying reward models are frozen; only the fusion weights per regime are updated. The multiplier's bound prevents a single run from collapsing a primitive to zero or amplifying it to drive the whole fusion.
    • Why. This is the slow loop paired with Reflective Reward Gating's fast loop. The fast loop removes irrelevant primitives on a rollout; the slow loop downweights primitives that are reliably misleading on a given emotion. The combination means the system does not need to re-train the primitives themselves, which is the expensive and unstable step: fusion weights per regime are the only things that change, and they change at a schedule the training operator controls.

Ablations

  • Reported, not numerically detailed in the abstract. The abstract commits to ablations of gating (which gate contributes most) and RewardMemory (effect of the between-run pass alone). Specifics (per-gate contribution, multiplier bounds) are in the full paper.
  • Backbone transfer. SD 3.5 and FLUX experiments test whether the gating + memory layer is a drop-in for non-HunyuanVideo generators; the abstract reports positive transfer but no comparative deltas.

Limitations

  • No public numeric table at launch. The HF abstract reports directional gains against SAGE-GRPO and transfer to SD 3.5 / FLUX, but no per-benchmark or per-emotion numbers are visible at the abstract level; verification requires the full PDF or the code release.
  • Reward models unchanged. EmoReward recalibrates fusion weights, not reward models. If a primitive is systematically wrong on a regime, bounded-multiplier recalibration only limits its contribution; it cannot fix the primitive. The paper accepts this as a design choice (cheap, stable), not a failure.
  • Emotion taxonomy not public. The regime set used to partition RewardMemory is not published alongside the HF submission; the gates (phase, face-confidence, conflict, subtlety) are described by name but not by threshold values.
  • No comparison to closed-weight generators. No head-to-head against Sora 2, Veo 4, or other proprietary video generators; the in-paper comparison set is other open methods under the HunyuanVideo-1.5 backbone.
