UEmbed: Unified Sparse and Dense Multimodal Embeddings

Tier 2 · Research Paper arXiv 2026-08-03 Multimodal retrieval · Decoder-only embedding · Sparse + dense unification · Open weights

Overview

  • Authors: Tingyu Song, Mingxin Li, Yanzhao Zhang, Dingkun Long, Pengjun Xie, Zhijie Nie, Yilun Zhao, Shu Wu (Alibaba-NLP, Tongyi Lab — the Qwen team’s embedding sibling org).
  • Positioning: Learned Sparse Retrieval (LSR) has so far been an encoder-only artifact (SPLADE lineage, bidirectional BERT-style backbones), and multimodal LSR extensions still bolt cross-modal encoders on top. UEmbed collapses the split by making a decoder-only multimodal LLM emit both a sparse lexical vector and a dense representation in one causal forward pass, on the same weights.
  • Ships three open-weight scales (2B, 4B, 9B), trained on entirely public data, plus a public GitHub repo. The 9B checkpoint reaches 71.8 dense / 71.0 sparse on MMEB-v2, beating public-data-trained baselines like RzenEmbed and remaining competitive with strong dense and sparse baselines on BEIR.
  • Named contribution receiving a mechanism explanation below: N-token vocabulary-partition sparse readout on a causal decoder.

Methodology

  • Named contribution — N-token vocabulary-partition sparse readout.
    • Problem. A decoder-only causal LM can naturally produce a dense embedding from the last token’s hidden state, but sparse lexical retrieval needs a per-vocab-item score. Reading a full-vocab softmax off one hidden state at inference forces the model to compress every retrieval-relevant lexical signal into a single vector, which is what dense embeddings do and what LSR was supposed to avoid.
    • Mechanism. UEmbed appends N learnable special tokens to the input sequence, and partitions the model’s vocabulary into N disjoint subsets. Each of the N tokens’ causal hidden state predicts sparse weights only over its assigned vocabulary subset, and the N subsets are concatenated to reconstruct the full sparse vector. The dense embedding is read from an additional pooling of the same hidden states in the same forward pass.
    • Why. The partition gives the model N different retrieval-conditioning contexts (one per special token) to specialize on different lexical slices, without needing multiple forward passes or a bidirectional readout head. That is what makes the sparse output competitive with the dense output on MMEB-v2 (71.0 sparse vs 71.8 dense at 9B). Improves over encoder-only SPLADE-style LSR by removing the bidirectional-encoder dependency — the same decoder LLM used for generation can now serve retrieval directly — and over prior decoder-only embedding work by adding a real sparse signal alongside the dense one.
  • Training data is entirely public. Modalities: text plus images, unified through the decoder’s shared token space.
  • Sparse and dense embeddings are produced in a single causal forward pass, so serving cost per query is one LLM forward regardless of which retrieval mode the downstream stack picks.

Evaluation and results

  • MMEB-v2: UEmbed-9B reaches 71.8 dense and 71.0 sparse. Publicly-data-trained multimodal embedding models (RzenEmbed cited as the direct comparator) are outperformed on both axes.
  • BEIR: competitive with strong dense and sparse baselines. The paper frames this as demonstrating that unifying sparse+dense within one decoder does not sacrifice text-only retrieval quality.
  • Ablations and utility demonstrations are structured along three dimensions: effectiveness (retrieval quality), efficiency (one forward pass yields both signals), and agentic applications (the same embedding model can serve retrieval calls inside agent tool use without a separate embedding stack).

Other

  • Repository: Alibaba-NLP/UEmbed. Model collection: UEmbed Collection. Project page: alibaba-nlp.github.io/UEmbed/.

SwanTale: Unified Multi-Speaker Speech and Audio Generation for Instruct and Zero-Shot Tasks

Tier 2 · Research Paper arXiv (#1 HF Daily Paper 2026-08-04) 2026-08-03 Speech + audio generation · Multi-speaker · Unified MoE · GRPO post-training

Overview

  • Authors: Yu Zhang, Ruiqi Li, Changhao Pan, Ke Lei, Xiang Yin, Cheng Yang (ByteDance / SwanAIGC).
  • Third entry in ByteDance’s SwanAIGC audio line, following SwanVoice (long-form zero-shot TTS for monologue and dialogue, May 2026) and SwanBench-Speech. SwanTale unifies the previously separate directions: expressive multi-speaker TTS, instruction-conditioned audio-scene generation (environments, effects), and voice reuse across sessions.
  • Two task families are trained jointly: an instruct task where the input is a caption describing environment, speaker styles, and fine-grained content, and a zero-shot task where the input is a reference audio clip plus the same fine-grained content. Both produce multi-speaker speech mixed with environmental audio in a single generation call.
  • Named contributions receiving mechanism explanations below: SwanData-Caption (multi-level caption annotation pipeline), SwanVAE (multi-audio-modality tokenizer), and Unified-MoE with Engram conditioning + reward-conditioned quality control. Also relevant: curriculum learning + GRPO post-training.

Methodology

  • Named contribution — SwanData-Caption.
    • Problem. Multi-speaker instruct-conditioned generation needs training samples annotated at multiple levels of description (per-speaker style, environment, dialogue-level content), but raw speech-and-audio corpora are annotated only at the utterance level or not at all, and the styles present in the wild are heavily biased toward clean single-speaker read speech.
    • Mechanism. The pipeline cleans raw speech-and-audio data, adds targeted synthetic coverage for under-represented styles (rare environments, expressive multi-speaker acoustic scenes), and annotates each sample with diverse and accurate multi-level captions spanning speaker style, environment, and fine-grained content.
    • Why. Multi-level captions are the training signal that lets one model handle both instruct and zero-shot tasks: instruct queries land at the caption level directly, and zero-shot queries use the fine-grained content field with the reference audio replacing the speaker/environment fields. Synthetic coverage fills the tails so that instruct queries on rare-style requests do not collapse to the corpus mode.
  • Named contribution — SwanVAE.
    • Problem. A single autoencoder tuned for speech loses fidelity on environmental audio (music, effects), and vice-versa; the SwanTale task family needs both, jointly, in one sequence.
    • Mechanism. SwanVAE is a purpose-built VAE for multi-audio-modality generation, tokenizing speech, effects, and music with a single latent codebook geometry so downstream MoE layers can attend across modalities without a per-modality encoder switch.
    • Why. A shared audio-tokenizer surface is what lets the Unified-MoE below train jointly on speech and audio tasks with one loss; earlier approaches used one tokenizer per audio modality and paid for it in cross-modal misalignment when the model had to mix, for example, environmental ambience under dialogue.
  • Named contribution — Unified-MoE with Engram conditioning and reward-conditioned quality control.
    • Problem. Multi-task multi-modality audio training routinely collapses onto whichever task dominates the loss (usually plain TTS), because the model has no principled way to keep speaker-style memories separate from environmental cues.
    • Mechanism. A single MoE backbone routes tokens across a set of experts shared across tasks, but incoming context is separated by Engram conditioning — a structured conditioning slot that carries reusable speaker/environment memories — and each generated segment is scored under reward-conditioned quality control, so the model can be sampled with an explicit target quality band at inference.
    • Why. Engram slots keep multi-speaker identity persistent across long generations without leaking speaker features into environmental ones; reward-conditioning gives the deployment operator a knob at inference (accept lower quality for speed, or spend for cinematic quality) without needing a separate model per operating point.
  • Training recipe. Curriculum learning on the SwanData-Caption pipeline output progressively strengthens the model on each task family, followed by GRPO post-training on the same reward-conditioned quality objective — the same RL algorithm family Alibaba deploys for Qwen and MiniMax deploys for H3 finds another use here for perceptual audio quality.

Evaluation and results

  • SwanTale leads on multiple key zero-shot and instruct metrics on the paper’s own SwanBench audio suite, and posts best-in-set expressiveness scores in both instruct and zero-shot settings. The paper claims support for complex instruct generation involving multi-speaker speech and audio.
  • The paper does not publish comparison numbers against non-Swan-family baselines in the abstract; downstream evaluators will want the full table.
  • Demos: swanaigc.github.io/#swantale. HF community page: 2608.02023.

DiffusionGemma Technical Report

Tier 2 · Technical Report arXiv · Google AI for Developers 2026-07-31 (arXiv) · 2026-06-10 (checkpoint) Discrete-diffusion LM · Gemma 4 fine-tune · Parallel decoding · MoE · Open weights

Overview

  • Authors: DiffusionGemma Team plus a full author list including Adrien Ali Taïga, James Assiene, Daniele Calandriello, Rahma Chaabouni, João Gante, Tamara von Glehn, Nate Keating, Chris Knutsen, Martin Kukla, Tianlin Liu, Ivan Lobov, Ofir Nabati, João Gabriel Oliveira, Nicolas Perez-Nieves, Nastasia Prutianova, Bobak Shahriari, Jean Tarbouriech, Pavel Tyletski, Çağlar Ünlü, Cindy Wu, Glenn Cameron and 22 more (Google DeepMind).
  • The technical report formalizes the training recipe behind the DiffusionGemma 26B-A4B-it open-weight checkpoint that shipped 2026-06-10 as vLLM’s first natively-supported diffusion LLM (see the vLLM blog). The checkpoint sits behind Google’s DiffusionGemma model card and the marketing landing at deepmind.google/models/gemma/diffusiongemma/. This is the first full public accounting of how DeepMind got there.
  • Named contributions receiving a mechanism explanation below: Block-parallel discrete-diffusion fine-tune of an AR MoE, Two-stage SFT-then-RL-with-sampler-distillation training pipeline, and Hybrid AR↔diffusion preservation via the same weights.
  • Framing consequence: DiffusionGemma is not trained from scratch; it is a fine-tune of the already-trained Gemma 4 mixture-of-experts model (25.2B total / 3.8B active), using fewer than 10% of the base model’s pre-training token budget. That budget scale is central to the paper’s claim: converting an AR model to diffusion is roughly a fine-tune, not a rebuild.

Architecture

  • Backbone. The already-trained Gemma 4 MoE, unchanged in weights topology — 25.2B total, 3.8B activated per token, thinking mode preserved, multimodal input preserved (text, image, video → text out), long context preserved.
  • Decoding regime. Iterative parallel refinement of blocks of 256 tokens. Each forward pass takes a partially-noised block, denoises in one shot, and the block converges over a small number of steps; averaged across the evaluation suite, DiffusionGemma accepts roughly 20 tokens per forward pass. At throughput, that translates to about 1,500 output tokens per second on a single NVIDIA H100 — described in the paper as substantially faster than AR models even with state-of-the-art speculative decoding.
  • Named contribution — Block-parallel discrete-diffusion fine-tune of an AR MoE.
    • Problem. AR decoding’s throughput floor is the sequential dependency: one token per forward pass, and even speculative decoding trades hits for a small multiplier. Training a diffusion LM from scratch to break that dependency costs a full pre-training run — unaffordable at the 25B-total scale of Gemma 4.
    • Mechanism. Instead of training from scratch, DeepMind fine-tunes the Gemma 4 MoE to parallel discrete denoising: the model no longer predicts the next token but iteratively refines a partially-noised block of 256 tokens, denoising in parallel until it converges. The training loss teaches the model bidirectional denoising over these blocks under masking rates that anneal during training.
    • Why. This yields ~20 accepted tokens per forward pass on average, and about 1,500 tokens per second per H100 — higher than what AR Gemma 4 achieves with state-of-the-art speculative decoding, at a fine-tune cost of <10% of Gemma 4’s original pre-training token budget. The whole thing is a Pareto move: for the same base capability, decode faster, and pay for it in fine-tune compute rather than pre-training compute. Improves over prior diffusion-LM efforts (Diffusion-of-Thoughts, SEDD, LLaDA) that started from scratch and could not reach Gemma-4-tier capability.
  • Named contribution — Two-stage SFT-then-RL-with-sampler-distillation training pipeline.
    • Problem. SFT alone teaches the model to denoise, but does not push either the acceptance rate per pass or the quality of the accepted tokens; without a second stage the model would sit at a much lower operating point than the report advertises.
    • Mechanism. Stage 1 is supervised fine-tuning: teach the model to reverse a masked-diffusion process on Gemma 4’s own text distribution — the SFT signal is standard cross-entropy under the diffusion denoising objective. Stage 2 combines reinforcement learning on generation quality with sampler distillation, jointly improving output quality and reducing the number of denoising steps needed per block.
    • Why. Stage 2 is what turns a diffusion-capable model into a fast one. Sampler distillation compresses the multi-step denoising trajectory into fewer steps without a quality collapse; the RL term on top ensures those fewer steps still land on high-quality outputs. Improves over one-shot SFT-only diffusion baselines that pay throughput to keep quality.
  • Named contribution — Hybrid AR↔diffusion preservation via the same weights.
    • Problem. Fine-tuning any AR model on a very different objective normally destroys the AR behavior; you get a diffusion model that can no longer decode autoregressively when that mode is more efficient for short outputs.
    • Mechanism. The DiffusionGemma weights retain the ability to do AR decoding with only minor performance degradation, alongside the new block-diffusion mode. There is no separate AR head or gate: the same forward pass supports both regimes at inference.
    • Why. Real serving loads are heterogeneous: short chat turns benefit from AR’s per-token latency, long structured outputs benefit from block-diffusion’s throughput. Keeping both on the same weights means one deployed model checkpoint covers both, and opens a path to hybrid diffusion-AR decoding (the paper flags this direction explicitly) where different sections of a single response are decoded in whichever regime is cheaper for that section.

Training data and compute

  • Base model. Gemma 4 MoE, already pre-trained.
  • Fine-tuning budget. Under 10% of Gemma 4’s pre-training token budget. The report frames this specifically as evidence that AR-to-diffusion conversion is a fine-tune-scale operation, not a rebuild-scale one.
  • Retained capabilities. Thinking mode, multimodal inputs (text, image, video), long context all carry through the fine-tune. The retained capabilities are one of the report’s central claims: nothing about diffusion decoding forces you to give up any of them.

Evaluation and results

  • Throughput. Roughly 1,500 output tokens per second on a single NVIDIA H100 GPU, averaged across the paper’s full evaluation suite. Approximately 20 tokens accepted per forward pass on the same average.
  • Quality. Establishes a new Pareto frontier on the trade-off between generation speed and model capability. The abstract does not quote per-benchmark deltas, but positions the model as competitive with the AR Gemma 4 baseline on standard evaluations while decoding substantially faster. The Google model card reports that DiffusionGemma significantly outperforms Gemma 3 and 3n on the internal safety suite while keeping unjustified refusals low — the diffusion fine-tune did not regress safety.
  • Preservation of AR mode. AR generation from the same weights sees only minor degradation, per the report; this is what makes the hybrid path feasible.

Availability

  • Open weights. google/diffusiongemma-26B-A4B-it on Hugging Face under the Gemma license.
  • Serving. First diffusion LLM with native vLLM support (June 2026); this arXiv report supplies the training methodology.
  • Docs. Google AI for Developers model card, DeepMind model page, diffusiongemma.org hosted try-it.

SKT: Skill-Use Training at Scale via Verified Synthetic Data Generation

Tier 2 · Research Paper arXiv 2026-08-03 Agent skills · Synthetic trajectory generation · Verified data · Skill-use SFT

Overview

  • Authors: Zelin Tan, Yiqun Zhang, Hao Li, Zhiyao Cui, Hejia Geng, Shao Zhang, Hangfan Zhang, Yang Chen, Xiaosong Wang, Lilong Wang, Zhenfei Yin, Shuyue Hu, Chen Zhang, Lei Bai (Shanghai AI Laboratory).
  • Framing: shipping a library of agent skills to a base model is not sufficient — the model still needs to identify, apply, and coordinate those skills to solve a task. SKT is a verified synthetic-data pipeline that closes that gap by turning a collection of skills into supervised trajectories the base model can learn from.
  • Named contribution receiving a mechanism explanation below: Verified, multi-stage skill-grounded trajectory synthesis pipeline.

Methodology

  • Named contribution — Verified, multi-stage skill-grounded trajectory synthesis pipeline.
    • Problem. Prior skill-use datasets are either scraped web trajectories (noisy and not skill-grounded) or single-skill demonstrations that never exercise multi-skill coordination. Neither trains the model to reliably identify which skill to invoke for a real task, and rejection sampling on rollouts throws away most of the compute spent.
    • Mechanism. The pipeline runs in three phases. (1) Skill-configuration selection. Given a pool of agent skills, SKT selects both single-skill and multi-skill configurations that are compositionally reachable. (2) Task synthesis with dual verification. Tasks are generated for each configuration and passed through both rule-based and agent-based verification, with feedback-guided repair for tasks that fail either check. (3) Trajectory generation with skill-substantive filter. Trajectories are rolled out against the tasks; SKT retains only successful trajectories that substantially use every required skill — a coverage filter, not just a success filter.
    • Why. The verifier is what makes the synthesis scale to millions of trajectories without collapsing quality: rule-based + agent-based cross-checking catches the two failure modes rule-only checkers miss (semantic drift) and agent-only checkers miss (spec violations). The coverage filter is what makes the resulting SFT signal actually train skill use, not just task completion — without it, models learn to solve tasks in whatever way avoids invoking the intended skills.
  • Scale. From 2,000 public agent skills, SKT produces 4,000 task packages and 27,164 verified trajectories. A disjoint held-out skill pool feeds a separate benchmark: SkillEval, released at Artemis0430/skilleval-v1.

Evaluation and results

  • Main SFT result. Supervised fine-tuning on SKT-generated trajectories consistently improves skill-use performance across diverse base models, benchmarks, and agent harnesses. The improvements hold across model families — SKT is a data recipe, not a model.
  • Verification ablation. Removing either the rule-based or the agent-based verifier degrades trajectory quality; both are needed. This is what makes the resulting SFT actually work.
  • Cross-harness evaluation. Gains transfer across agent interfaces, not just the harness the trajectories were synthesized under — skill-use skills learned this way are portable.
  • Scaling. Skill-use performance increases with broader skill coverage in the synthesis pool, indicating the pipeline is not saturated at 2,000 skills.

Ablations

  • Removing verified filtering degrades the trained model’s skill-use rate materially; the “successful trajectory + substantive skill use” conjunction is doing real work.
  • The paper positions verified synthetic data as an effective and scalable substitute for human-annotated skill-use traces — the human bottleneck is what makes prior skill-use SFT expensive to scale.

Other

  • Held-out benchmark: SkillEval-v1. Built with the same SKT pipeline on a disjoint skill pool so scores are directly comparable across models.

DAPD: Dual-Anchored Policy Distillation

Tier 2 · Research Paper arXiv 2026-08-03 On-policy distillation · Post-training · Privilege illusion · Qwen3 fine-tuning

Overview

  • Authors: Jianyu Wu, Yizhou Wang, Encheng Su, Chen Tang, Shixiang Tang (Shanghai AI Laboratory).
  • Directly targets a live failure mode in the on-policy self-distillation (OPSD) recipe that recent open-weight models — Inkling-Small most visibly (see the 2026-08-03 review) — use to have a smaller student beat a larger teacher.
  • Named contribution receiving a mechanism explanation below: Dual-Anchored Policy Distillation (DAPD), decomposing into Dual-Path Anchoring (DPA) and Dual-Source Anchoring (DSA).

Methodology

  • Named contribution — DAPD: Dual-Path Anchoring plus Dual-Source Anchoring, targeting the privilege illusion.
    • Problem. OPSD strengthens the teacher with privileged information (fuller context, hidden reasoning traces, oracle signals) so the teacher labels student rollouts more reliably. But the student is inference-time deprived of that privilege. When the student trains against a privileged teacher signal it can pick up privilege-dependent behavior — behavior that only makes sense when the privileged information is available — and continue emitting it at inference as if the privilege remained. This is the privilege illusion, and it degrades downstream performance.
    • Mechanism.
      • Dual-Path Anchoring (DPA). A self-conditioned bridge aligns the reference behavior (privileged) and the rollout behavior (student, unprivileged) along two matched-information paths. The paths carry the same information conditioning, so anything the reference does with privileged context that the rollout cannot reproduce is not flowed into the student’s training signal.
      • Dual-Source Anchoring (DSA). Applies the same paths in both directions: reference-to-rollout and rollout-to-reference. This reduces the student’s reliance on privileged reference guidance while preserving correctness supervision, because DSA still lets the correctness signal cross the anchor.
    • Why. The two-anchor structure isolates information asymmetry as the root failure mode of OPSD, then explicitly neutralizes it while retaining the correctness supervision that made OPSD useful in the first place. Improves over vanilla OPSD by strictly dominating it on the same base checkpoint; the fix is at the loss-and-conditioning level, not a new algorithm.

Evaluation and results

  • On Qwen3-4B, DAPD lifts average across-task performance by +2.00 points relative to vanilla OPSD.
  • Gains scale monotonically with model size in the reported grid: +2.69 at Qwen3-4B, +2.78 at Qwen3-32B (both are averaged across the paper’s task suite — the abstract does not enumerate the individual benchmarks).
  • The consistent-with-scale delta is the paper’s key claim: the privilege-illusion pathology of OPSD is not a small-model artifact that vanishes with scale, so a fixed recipe that pays down that debt keeps paying.

Ablations

  • Extensive ablations verify that both DPA and DSA are individually load-bearing; removing either recovers most of the OPSD failure mode.

Other

  • Directly relevant to open-weight labs currently relying on OPSD-style pipelines — a small change to the distillation recipe recovers a systematic gap. Worth pairing this with the on-policy distillation section of the 2026-08-03 Inkling-Small review.
