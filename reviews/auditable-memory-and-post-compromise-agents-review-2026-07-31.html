SecRespond: Benchmarking AI Agents for Real-World Post-Compromise Incident Response

Tier 2 · Benchmark arXiv 2607.26791 2026-07-29 Cybersecurity · Agent evaluation · Incident response

Overview

  • Existing LLM cybersecurity benchmarks are pre-compromise: the agent is placed in a clean environment before the attack, and the task is to detect or exploit. SecRespond flips the setting to post-compromise: the box has already been breached, the disk snapshot is dirty, and the agent’s job is to reconstruct what happened and stop it happening again. This is where security operators actually spend their time, and where prior benchmarks provide no signal.
  • Alibaba-NLP submission (Wang, Chen, Ding, Xie, Huang, Liu, Wang, Lei, Ouyang, Li). Benchmark instantiates the task across 10 cyber ranges, each a distinct compromised cloud host, spanning 4 entry-point types, 21 ATT&CK techniques, and 5 operating systems. 23 frontier LLMs are evaluated on the OpenCode agent harness. Headline finding: no model achieves complete detection and remediation on any single range.

Methodology

  • Problem. Post-compromise incident response is a mixed workload: some findings are surfaced by the host security product (alerts, vulnerability scans, baseline checks) and can be triaged from those signals alone; other intrusions are silent, and the agent has to proactively investigate the disk artifact to find indicators of compromise. Pre-compromise benchmarks measure the first skill (react to a known problem) but not the second (find an unknown one). A benchmark that only reports aggregate success rates cannot distinguish an agent that reads alerts well from one that hunts silently.
  • Mechanism. Each SecRespond instance is a forensic disk snapshot of a compromised cloud host paired with the reports emitted by a real host security product: alerts, vulnerability scans, and baseline configuration checks. The agent, running the OpenCode harness (host artifacts + CLI access), must produce four deliverables: (i) a forensic report on the intrusion, (ii) a forensic report on baseline configuration risks, (iii) a forensic report on vulnerability risks, and (iv) a remediation plan. Task construction spans 4 entry-point types (i.e. how the attacker got in), 21 ATT&CK techniques (what they did once inside), and 5 OSes (Linux distributions and Windows variants). Evaluation grades detection and remediation separately, and per-range, exposing where the agent covered alert-driven findings but missed silent intrusions.
  • Why it works / why it beats prior. Existing agentic-security benchmarks (CyberSecEval, InterCode-CTF, and pre-compromise capture-the-flag setups) place the agent in a clean, single-vulnerability environment and score whether it finds a planted flag. That measures exploit competence but not investigative behavior on a dirty disk. SecRespond’s post-compromise framing keeps the CLI-based tool interface familiar to existing agents but forces the agent to reconcile disk artifacts with security-product reports, and its per-range grading of detection versus remediation makes the specific failure mode (silent-intrusion hunting) identifiable rather than lumped into an aggregate score. The result — agents reliably uncover alert-exposed problems but fail to proactively investigate for silent intrusions and cannot produce comprehensive verified remediation plans — is what the benchmark was built to surface.

Evaluation & results

  • 23 frontier LLMs evaluated through the OpenCode agent harness.
  • Agents reliably uncover the problems exposed by alerts from the host security product.
  • Agents struggle to proactively investigate the disk for silent intrusions and to produce comprehensive, verified remediation plans.
  • No model achieves complete detection and remediation on any single range.
  • Task family spans 4 entry-point types × 21 ATT&CK techniques × 5 operating systems across the 10 cyber ranges.

Other

  • Benchmark publicly available at Alibaba-NLP/qqr/tree/main/data/secrespond.
  • Paper positions the failure as a fundamental bottleneck for real-world incident-response agents, not a scaffolding or prompt problem: the missing skill is turning a dirty disk plus partial telemetry into a full attack reconstruction.

Voice Memory for Agentic Speech Recognition

Tier 2 · Research Paper arXiv 2607.26410 2026-07-29 ASR · Text-space optimization · Test-time adaptation · Agentic systems

Overview

  • Modern read-speech ASR is below 2% WER, so the corrector’s dominant decision is no longer which hypothesis to pick but whether to edit the 1-best at all. Unconstrained generative error correction (GER) at that operating point over-corrects: it fluently rewrites tokens that were already right, moving output away from the reference. Voice Memory reframes correction as a per-utterance act/abstain decision made by a frozen corrector reading a per-domain, human-readable text memory.
  • NVIDIA submission (Yang, Chen, &Z.dot;elasko, Chen, Balam, Ginsburg). The paper introduces a listener-thinker (LT) architecture: the synchronous listener decodes and decides at stream time, the asynchronous thinker rewrites the memory between utterances. Across ten HyPoradise domains with an open corrector, weighted WER falls 8.36% → 7.52% (7.47% with 3 in-context examples) with no dataset regressed below its 1-best baseline; harmful edit rate on wsj falls 64% → 35%; the deployed wsj memory is 776 bytes.

Methodology

  • Problem. At sub-2% WER, the corrector must choose whether to modify the hypothesis. Fine-tuning, LoRA, and soft prompts encode that decision in weights or continuous vectors that cannot be inspected, transferred across model families, or reverted without retraining; few-shot exemplars pay a token cost per request. None yields adaptation that is simultaneously inference-only, auditable, and portable across correctors.
  • Mechanism. Voice Memory formalizes correction as the listener-thinker (LT) format, a tuple (B_φ, M_θ, π, s, Op): a frozen ASR decoder B_φ emits n-best textual evidence H; a frozen corrector M_θ holds a persistent inspectable text state s ∈ Σ* (a short Markdown file, the memory); the policy π(a | H, s) chooses per utterance between act (return M_θ(H, s)) and abstain (return the 1-best h_1); an asynchronous score-gated optimizer Op revises s from failure and success rollouts through bounded add/delete/replace edits, accepting an edit only when it strictly improves a held-out score. Adaptation to a domain therefore happens through forward passes only, with no gradients and no weight updates. The two roles are coupled solely through s, so the learned skill is auditable and portable to correctors from other model families.
  • Why it works / why it beats prior. The optimizer discovers restraint as the operative skill: because acceptance is gated on a held-out score, the corrections the loop keeps are those that suppress rewrites — the deployed memories read like “keep the verbatim ASR token; do not normalize” and “place ‘dollars’ after the amount, not ‘$’ before it.” This is exactly the policy the low-WER regime needs: over-correction is the failure mode, and the memory writes it out of the frozen corrector without touching weights. Prior alternatives (RobustGER, NeKo) read the noise condition into a latent vector and pay for it with a training run; the same signal is instead written into a per-noise-family text memory read at inference.
  • The paper also introduces two diagnostics: the Recoverable Information Ratio ρ = (WER_{1-best} − WER_{&yhat;}) / (WER_{1-best} − WER_{oracle}), which measures how much of the 1-best-to-n-best-oracle WER gap a correction closes (ρ > 1 means recovering tokens present in no hypothesis, going below the oracle bound), and the Harmful Edit Rate, the fraction of token edits that break a correct token, which isolates over-correction from WER.

Evaluation & results

  • Frozen corrector: open-source MiniMax-M3 (~428B, 1M context) serves as both corrector and optimizer. Semantic scoring gate uses all-MiniLM-L6-v2 (4-bit) on-device.
  • HyPoradise v0 across ten domains under disjoint train/test splits; Whisper 5-best hypotheses with references.
  • Weighted WER: 8.36% → 7.52% (Voice Memory, semantic-gated), → 7.47% with three added in-context examples. No dataset regresses below its 1-best baseline.
  • Air-travel commands (atis): 8.40% → 3.40%, ρ = 0.96 (Voice Memory closes 96% of the 1-best-to-oracle gap).
  • Noisy far-field speech (CHiME-4): 12.69% → 10.46%, matching training-based robust correction without fine-tuning or latent noise embeddings.
  • Financial news (wsj): unconstrained zero-shot GER raises WER above the 1-best; Voice Memory reduces harmful edit rate from 0.64 → 0.35. Deployed wsj memory is 776 bytes.
  • Per-domain ρ: atis 0.96, cv 0.59, wsj 0.48, chime4 0.21, lrs2 0.16, coraal 0.15, ls_other 0.06. Near-floor domains (td3, ls_clean) go slightly negative (ρ = −0.09, −0.11), consistent with restraint being the correct policy where recoverable headroom is exhausted.
  • Across nine domains, per-domain gain from correction tracks recoverable headroom with correlation r = +0.90, delineating the operating regime in which a corrector should act.

Ablations

  • Portability. A memory written by one model family improves a corrector from a different family; that second corrector can then re-form its own memory with the same loop. Transfer follows the same recoverable-headroom scaling. The memory transfer generalizes beyond ASR to a translation mini-study.
  • Provenance. Quality of the source rollouts beats coverage: memories distilled from a smaller high-quality trajectory set outperform memories built from a larger noisier one.
  • Adaptation cost. Order-of-magnitude figures: ~10^2 utterances at forward-only inference time, minutes wall-clock, <10 KB artifact, versus fine-tuning at 10^3–10^4 utterances, hours wall-clock, GB/MB adapter, and no auditability or reversibility.
  • Semantics vs. surface error. A semantic training signal produces lower final WER than a WER-only training signal, formalized as a surface-to-meaning gap measured on the ASR outputs.
  • Corrector-agnostic memory. Appendix C runs a Claude case study showing memory transfer across a proprietary-to-open corrector pair.

Other

  • Reference implementation and demo at huckiyang.github.io/voice-memory; checkpoint at huckiyang/voice-memory; NeMo-Speech integration at NVIDIA-NeMo/Speech.
  • WER and harmful edit rate computed with the open-source agwer package (MIT), designed to be safe as a reward target inside the optimization loop.
  • The LT format is positioned as the speech instance of the interaction/background split now emerging at the frontier — a synchronous interaction path coupled to an asynchronous background optimizer through a single persistent artifact.

Tsinghua KEG

Memory for Large Language Models

Tier 2 · Survey arXiv 2607.25380 2026-07-28 Survey · LLM memory · Architecture taxonomy

Overview

  • Memory in LLMs has shifted from an implicit byproduct of attention to an explicit, controllable architectural dimension — transient attention state, recurrent state dynamics, parameter-efficient adaptations, and scalable lookup storage now coexist in shipping systems. The research landscape has fragmented into incomparable proposals. This survey imposes a shared taxonomy so that new memory mechanisms can be argued against a common frame.
  • Tsinghua KEG submission (Zhoubian, Zhang, Kharlamov, Tang — Jie Tang leading). 20 pages, 4 figures. Positioned not as a benchmark or method but as the organizing framework in which competing memory mechanisms — from KV-cache extensions to text-space memories like NVIDIA’s Voice Memory — can be directly compared.

Methodology

  • Problem. Recent memory work spans transient attention, recurrent state, parameter-efficient adaptations, and scalable lookup storage. The mechanisms differ in where memory lives (activations vs. addressable storage), when it is written (online vs. offline), and how long it persists (single-turn vs. cross-session). Absent a taxonomy, hybrid memory architectures cannot be argued for on principled grounds and system-level efficiency trade-offs remain implicit.
  • Mechanism. The survey characterizes each memory design along three orthogonal axes:
    • Representation: implicit (memory lives inside the computation graph, e.g. attention state, hidden states) vs. explicit (memory is an independently addressable object, e.g. a retrieval store, a persistent text artifact).
    • Update dynamics: offline (memory changes only through a training run) vs. online (memory changes during inference).
    • Persistence: short-term (bounded by a context window or session) vs. long-term (spans sessions).
    On top of the axes, the survey formalizes the granular mechanisms that determine how each memory design writes, routes reads, transitions state, and consolidates entries. The classification distinguishes computation-coupled memory (bound to the model’s forward pass) from independently addressable memory (an external artifact or store).
  • Why it works / why it beats prior. Earlier surveys either enumerate memory-augmented architectures without a shared frame or fold memory into a general retrieval-augmented-generation discussion. The three-axis characterization is chosen so that the axes are actually independent in practice: a KV-cache-extension paper (implicit / offline / short-term), a MemGPT-style external store (explicit / online / long-term), and a text-space memory like Voice Memory (explicit / online / long-term, but pure natural language) each occupy distinct cells. Argueing about a proposal’s trade-offs then reduces to naming which axis it moves along.

Evaluation & results

  • Survey; no benchmark results. The paper delivers the taxonomy plus a critical analysis of hybrid memory architectures, system-level efficiency trade-offs, and multi-dimensional evaluation methodologies.
  • The evaluation-methodology discussion pushes back on single-metric memory evaluation — recall on a needle-in-a-haystack task and throughput at a context length are not commensurable and should not be traded for one another without a stated Pareto frame.

Other

  • Positioned as the framework in which the day’s other paper — NVIDIA’s Voice Memory — sits cleanly on the “explicit / online / long-term” corner alongside external memory stores, while the KV-cache extensions and recurrent state mechanisms it discusses occupy the opposite corners.
