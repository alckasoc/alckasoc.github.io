AutoSaddler: Automatic Harness Optimization with Durable Updates from Agent Execution Traces

Tier 2 · Research Paper arXiv 2026-08-24 Agent harnesses · Auto-optimization · Long-horizon agents · GAIA2 · SWE-Bench Pro

Overview

  • Sungho Park, Wonjoong Kim, Rongyuan Tan, Jue Zhang, Wook-Shin Han, Pengfei Gao, Chanyoung Park, Yongqiang Yao, Rao Fu, Elsie Nallipogu, Qingwei Lin, Saravan Rajmohan, Dongmei Zhang (Microsoft, with internship affiliations at KAIST, SUSTech, and POSTECH; corresponding authors at Microsoft). arXiv:2608.23041v1 [cs.AI], 44 pages / 15 figures, submitted 2026-08-24, on the Hugging Face Daily selection for 2026-08-26.
  • The framing: LLM agent reliability on long-horizon tasks depends heavily on the surrounding harness (prompts + tool configurations + runtime control logic), but harness design remains a manual and expensive search. AutoSaddler recasts it as an offline learning problem — iteratively update the harness from failure signals over mini-batches of training tasks — and instantiates the loop with three session-scoped agents built on the Claude Agent SDK (CA-SDK). Base harnesses used at eval: default ReAct on GAIA2, SWE-agent on SWE-Bench Pro, Terminus 2 on Terminal-Bench 2.0; underlying LLM: Claude Opus 4.6.

Methodology

  • Named contribution 1 — formulate harness optimization as offline mini-batch learning over textual harness parameters.
    • Problem. Prior automated-harness work either optimizes prompts only (GEPA-style textual gradients) or edits the harness end-to-end with an unstructured coding-agent loop (Meta-Harness). The first misses tools and middleware; the second lacks explicit control over generalization, so patches overfit to the trajectories they were derived from. Neither treats the harness as a parameter θ that gets updated by mini-batch signals with a dev-set selection rule.
    • Mechanism. AutoSaddler defines the harness parameter as θ = (θprompt, θtool, θmiddleware) ∈ Θ, partitions tasks into Dtrain/Ddev/Dtest, and at each iteration n (i) evaluates the current harness on a mini-batch Bn, (ii) runs Diagnosis-Patch to derive a structured patch Δθn against failure traces, (iii) verifies mini-batch improvement ĴBn(H'n)>ĴBn(Hn), (iv) if accepted, further evaluates H'n on Ddev for generalization. After the rollout budget is exhausted the framework returns the dev-max candidate and evaluates once on test.
    • Why it works / why it beats prior. Treating textual harness edits under the same train / dev / test discipline as ordinary machine learning gives explicit control over the overfitting axis; the mini-batch update, the mini-batch verifier, and the dev-set generalization check play the roles of forward, backward, and validation in standard mini-batch SGD, except that "backprop" is realized by the Diagnosis-Patch textual-gradient step. GEPA operates only over prompts and Meta-Harness treats the whole harness as free-form code without an explicit generalization guard; AutoSaddler beats both because targeting the joint (prompt, tool, middleware) space is broader than prompt-only, and the dev-set generalization guard prevents unbounded editing from collapsing onto a single trajectory.
  • Named contribution 2 — Diagnosis-Patch Session with a structured patch taxonomy and Phased Patch Scheduling.
    • Problem. Long-horizon agent traces do not fit in an LLM context window, and diagnosis without evidence collapses to shallow reflection. Simultaneously, an unconstrained editor produces a wide, sparsely useful patch distribution — many patches touch orthogonal harness components and cannot be attributed to a specific failure mode.
    • Mechanism. The Diagnosis-Patch Agent (on CA-SDK) is given the failure trace plus the harness codebase; structured guidance lets it progressively retrieve relevant trace details, mitigating the long-context problem. It identifies the suspected root cause, considers alternative hypotheses, and produces a structured patch Δθn under a fixed taxonomy: Prompt Patch (Rule Addition / Rule Modification), Tool Patch (New Tool Addition / Argument Modification / Implementation Fix / Tool Description Fix), Middleware Patch (PreToolUse Hook / Infrastructure Change / Agent Loop Logic Change). Subtypes are further grouped into Capability patches (execution / orchestration edits) and Steering patches (textual edits only). Phased Patch Scheduling runs Capability first, Steering second — the same shape as a learning-rate schedule in standard training.
    • Why it works / why it beats prior. Grounding diagnosis in the actual traces (rather than in surface reflection) is what turns "the run failed" into "the run failed because tool X's argument scope was too permissive." A fixed taxonomy over three harness components makes each patch attributable and comparable across iterations. Phasing Capability before Steering avoids the failure mode where a Steering patch masks a Capability bug and prevents the harder fix. Meta-Harness and GEPA lack both the taxonomy and the phase schedule.
  • Named contribution 3 — Reflection Session and Evolution Session on EvoDAG for durable, generalization-aware updates.
    • Problem. A one-shot patch that improves the current mini-batch may regress on a later one; a linear chain of edits also drops useful components once a superseding edit is written. Prior harness search does not maintain the population of prior harnesses in a form the optimizer can revisit and recombine.
    • Mechanism. After each patch, the Reflection Agent compares pre- and post-patch behavior on the same mini-batch and categorizes each outcome as fixed, regressed, still-failing, or still-passing; category-specific self-reflection prompts elicit lessons about why the patch was effective, which failure patterns it addressed, why regressions occurred, or why the patch was insufficient. Lessons are stored as node-level attributes in EvoDAG, a directed acyclic graph 𝒢=(V,E) where nodes are previously explored harnesses annotated with lessons and performance signals, and edges are the concrete diffs Δθ. The Evolution Session then instructs the Evolution Agent to synthesize the next harness Hn+1 by composing elements from any subset of prior harnesses, guided by the accumulated lessons — a merge operation analogous to evolutionary crossover.
    • Why it works / why it beats prior. EvoDAG turns the optimization trajectory from a chain into a graph, so the optimizer can escape local optima by recombining components from different lineages; the reflection categories give the recombination signal (a "regressed" case flags which component not to keep). Linear chains (GEPA-style) cannot recover discarded but useful edits, and Meta-Harness's unstructured coding-agent loop lacks the cross-lineage merge operator.

Evaluation & results

  • Benchmarks and base harnesses: GAIA2 (default ReAct), SWE-Bench Pro (SWE-agent), Terminal-Bench 2.0 (Terminus 2). Data splits enforce cross-task-group generalization — e.g. on SWE-Bench Pro, training is on qutebrowser, dev is on Vuls and NodeBB, test is on Ansible, Flipt, and Element-web. Metric: Pass@1, mean ± standard deviation over three test runs.
  • Headline gains over base harness: +9.0pp on GAIA2, +9.6pp on SWE-Bench Pro, +10.0pp on Terminal-Bench 2.0. Gains over the strongest automated baseline (GEPA or Meta-Harness, whichever is stronger on that benchmark): +7.4pp, +4.4pp, +6.7pp respectively.
  • GAIA2 test Pass@1 across three evaluated Universes (avg):
    • Default Agent (Manual): 53.0 ± 15
    • GEPA (Auto): 54.6 ± 25
    • Meta-Harness (Auto): 53.2 ± 22
    • AutoSaddler: reported to reach the best average across the three Universes.
  • Efficiency on GAIA2 dev: AutoSaddler reaches 72.3% dev accuracy with ~1,000 total task executions, while GEPA and Meta-Harness saturate at 64.6% and 61.5% respectively despite consuming ~2,800 task executions; on rollouts leveraged for optimization, AutoSaddler hits its best after 147 traces, roughly 10× fewer than Meta-Harness's 1,400.

Ablations

  • RQ1 — in-depth diagnosis vs shallow reflection: removing the evidence-grounded diagnosis step (retrieval over the trace + harness codebase) degrades root-cause identification and downstream patch usefulness; qualitative case studies attribute the gap to the ability to follow long-horizon causal chains rather than reflect on surface symptoms.
  • RQ2 — structured intervention vs unconstrained editing: restricting the patch space to the fixed prompt / tool / middleware taxonomy improves patch diversity per accepted update and reduces regressions; unconstrained editing tends to concentrate patches on prompts and misses tool and middleware fixes.
  • RQ3 — generalization-aware selection vs trajectory-specific repair: dropping the dev-set generalization guard collapses gains — patches that improve the mini-batch fail to transfer to the dev distribution; the guard is what prevents overfitting to the observed training samples.
  • Additional appendix analyses (in the 44-page report): robustness to optimization stochasticity, robustness to training-distribution shift, cross-model transferability to a weaker agent backbone, patch durability, optimization efficiency on Terminal-Bench 2.0, end-to-end cost characterization (optimizer-side vs task-agent evaluation cost), and a search-trajectory visualization plus a catalog of discovered patches on GAIA2 and Terminal-Bench 2.0.

Other

  • Implementation: Diagnosis-Patch, Reflection, and Evolution agents all instantiated via Claude Agent SDK. Base LLM at eval: Claude Opus 4.6. Project site and code: aka.ms/AutoSaddler-website. The appendix formalizes AutoSaddler as mini-batch learning over textual harness parameters — mapping Diagnosis-Patch-Verification to backprop-under-textual-gradients and mapping EvoDAG + Evolution to the optimizer update — and discusses where the analogy holds and where it breaks.

CAFE: Self-Improving Search Agents Need Co-Evolving Feedback

Tier 2 · Research Paper arXiv 2026-08-25 Agentic RL · Search agents · Critic co-evolution · GRPO · Preference optimization

Overview

  • Boyang Liu, Senjie Jin, Peixin Wang, Zhangyue Yin, Yibo Wang, Yuhao Zhou, Xinbing Liang, Shizheng Zhu, Yuhui Wang, Jingqi Tong, Zhiheng Xi, Jiazheng Zhang, Clive Bai, Clarenceai, Blaze Chen, Tao Gui, Qi Zhang, Xuanjing Huang (Fudan University with LLM Department, Tencent; Tencent-affiliated co-authors on @tencent.com). arXiv:2608.24794v1 [cs.AI], submitted 2026-08-25, on the Hugging Face Daily selection for 2026-08-26.
  • The framing: outcome-supervised search agents learn when and how to retrieve external evidence, but their terminal task reward cannot localize an in-flight directional error or redirect an ongoing trajectory. Prior in-context feedback methods (Reflexion, Self-Refine, CRITIC) return post-hoc critiques from prompted rather than trained models. CAFE makes corrective feedback a learned in-trajectory intervention emitted by a critic role that shares parameters with the agent, and alternates online agent-role updates with offline critic-role refinement so the two capabilities co-evolve. Backbone: Qwen2.5-7/3B-Instruct. Teacher for SFT bootstrap: Kimi-K2.5.

Methodology

  • Named contribution 1 — In-Trajectory Feedback Interaction with a Role-Conditioned Agent–Critic Model.
    • Problem. In long-horizon search, an early directional error compounds silently — the trajectory begins correctly but ends in failure and the terminal reward cannot say where. In-context feedback that could redirect the active trajectory is missing from outcome-supervised agents, and maintaining a separate critic model incurs substantial overhead.
    • Mechanism. The agent's action space is augmented with an optional <request_feedback> action. When emitted at intermediate history hi,t, the same shared-parameter model is invoked in the critic role qCθ(· | hi,t) to generate feedback fi,t; that feedback is appended to the context and control returns to the agent role πAθ, which continues the rollout from the augmented history. The two roles remain distinct at inference time but share a common backbone. The pair is bootstrapped via Bootstrapping Feedback-Conditioned Search: failed base-agent trajectories are diagnosed by Kimi-K2.5 which identifies the earliest turn where the trajectory becomes erroneous or ceases to make progress; the correct-so-far prefix is preserved, a <request_feedback> is inserted, and a teacher-generated feedback plus a feedback-conditioned continuation reach the correct final answer. Only actually-repaired trajectories are retained as SFT data.
    • Why it works / why it beats prior. Sharing parameters between agent and critic sidesteps the frozen-critic misalignment problem — as the agent's failure distribution shifts through training, the critic's judgment shifts with it. Bootstrapping from the base agent's own failure prefixes (rather than pure teacher rollouts) means SFT teaches the model to request, generate, and use feedback at states its own policy actually visits — the classic failure of pure teacher-imitation baselines like Reflexion is that the critique states are off-policy.
  • Named contribution 2 — Comparative Feedback Estimate reward and Feedback-Aware Advantage Shaping (online RL).
    • Problem. With feedback as an optional intervention, the terminal outcome does not reveal (a) whether a request was beneficial (a rescued trajectory and a flawless one both look like reward-1) or (b) how credit should be split across the pre-request prefix (which drove the search off course) and the post-feedback continuation (which repaired it). Vanilla GRPO assigns one advantage Ai to every trainable token in a rollout, which rewards the misbehaving prefix as much as the recovery.
    • Mechanism. Two additions to the standard GRPO pipeline. (i) CFE reward: within a prompt-level rollout group 𝒢x, split rollouts into call group (Ci=1, feedback requested) and skip group (Ci=0); the prompt-level empirical success gap û(x) = mean(r | call) − mean(r | skip) is used as the estimated feedback utility. The CFE-shaped reward is RCFEi = ri,task + βCiui − γ[nfb,i−1]+, penalising only requests beyond the first. (ii) Feedback-aware advantage shaping: trainable agent tokens in each requesting rollout are split at the first request into Tprei / Tcalli / Tposti. With clipped prompt-level gap gi=clip(ui,0,b), when Ai>0 and gi>0, the pre-request tokens receive max(Ai−λgi,0), the call tokens receive Ai, and the post-feedback tokens receive Ai+λgi. Observation and feedback tokens are excluded from the policy loss.
    • Why it works / why it beats prior. The call-vs-skip gap gives an on-policy, per-prompt estimate of feedback utility without a separate value head, so the agent learns to request feedback exactly when the prompt-level distribution says it helps. Splitting the advantage into pre / call / post spans stops the standard-GRPO failure where reinforcing a rescued rollout rewards the flawed behavior the agent had to abandon: the reweighting subtracts credit from the misbehaving prefix and adds it to the recovery. The clipping (gi∈[0,b]) and the "apply only when Ai>0" gate bound the influence so it never dominates the task reward.
  • Named contribution 3 — Rollout-Derived Preference Optimization (offline critic) and iterative co-evolution.
    • Problem. The critic's supervision cannot come from ground-truth feedback labels (there are none), and terminal-outcome supervision for the critic is confounded by both the search prefix and the agent's subsequent actions; a static critic misaligns with the agent as the agent's failure distribution shifts.
    • Mechanism. RDPO mines matched successful and unsuccessful trajectories from the latest online rollouts and forms preference pairs whose prefix is identical up to the request turn — so the pair differs only by the feedback generated and its downstream continuation. Standard preference-optimization then updates the critic role toward feedback that leads to the successful continuation and away from feedback that leads to failure. CAFE alternates online agent-role RL with offline critic-role RDPO on the latest rollouts.
    • Why it works / why it beats prior. Prefix matching is the specific device that removes the search-prefix confound — whatever the pre-request behavior was, both trajectories share it. Alternating agent- and critic-role updates keeps the critic aligned with the current agent's failure distribution; one-sided ablations show that improving only the agent or only the critic eventually plateaus, whereas alternating updates continues to improve performance. Frozen-critic baselines (prompted reflection methods) cannot track the shifting failure distribution.

Evaluation & results

  • Backbones: Qwen2.5-7B-Instruct and Qwen2.5-3B-Instruct. Evaluation: seven agentic SearchQA benchmarks plus BrowseComp-Plus.
  • Headline: at the 7B scale, CAFE achieves the strongest average performance among competing RL-based search methods, outperforming the strongest baseline by +2.1 EM and +1.3 F1. Gains transfer robustly to the 3B scale.
  • Out-of-domain generalization: gains are consistent across all six out-of-domain benchmarks.
  • Answer-level hallucination: average rate drops from 17.6% to 12.6% — a direct measurement of factual failure mode rather than a proxy metric.

Ablations

  • Component ablations (online): removing the CFE reward (feedback term or repeat penalty) or the feedback-aware advantage shaping degrades performance; the two mechanisms are complementary and needed for the reported gain.
  • Component ablations (offline): removing RDPO or replacing prefix-matched preference pairs with terminal-outcome preference pairs increases variance and cuts the average benchmark score, consistent with the paper's confounding argument.
  • Co-evolution schedule: one-sided ablations (only agent updates or only critic updates) plateau after a few iterations; alternating agent-then-critic updates continues to improve, empirically motivating the co-evolution framing.
  • Additional analyses (from the appendix TOC): model-size ablation, detailed hallucination results, iteration-schedule ablation, and results on BrowseComp-Plus.

Other

  • Positioning: CAFE separates itself from the finer-grained credit line (information gain, confidence change, local state comparison) which is evaluative (assigns credit retrospectively) rather than instructive (redirects the active trajectory). It also separates itself from Reflexion / Self-Refine / CRITIC by making the critic a trained shared-parameter role rather than a frozen prompted model. The Fudan / Tencent collaboration credentials the practical deployment reading (LLM Department, Tencent Inc. per author email affiliations).

WeMM-Embedding: WeChat Multi-Modal Embedding Technical Report

Tier 2 · Technical Report arXiv 2026-08-25 Multimodal embeddings · MMEB-v2 SOTA · Qwen3.5 backbone · WeChat deployment · MRL

Overview

  • Junjie Zhou, Ke Mei, Lei Li, Tianyi Wang, Fengyun Rao, Jing Lyu (WeChat Vision, Tencent Inc.). arXiv:2608.24053v1 [cs.CV], submitted 2026-08-25, on the Hugging Face Daily selection for 2026-08-26.
  • The framing: universal multimodal embeddings anchor retrieval, recommendation, classification, and agentic pipelines; WeMM-Embedding ships a family of MLLM-based universal embedding models at 2B, 4B, and 9B that supports text, images, videos, visual documents, and arbitrarily interleaved multimodal inputs with flexible output dimensions via Matryoshka Representation Learning. Training is two-stage: large-scale multi-task alignment, then curated fine-tuning with graded relevance supervision, hard-negative enrichment, and cross-scale distillation. All variants are natively multimodal Qwen3.5-backbone based.

Methodology

  • Named contribution 1 — unified pair-based training format with duplicate-aware masking.
    • Problem. The training corpus fuses weakly supervised web pairs, caption pairs, retrieval pairs, classification pairs, multimodal QA pairs, and graded-relevance pairs across text, image, video, and interleaved inputs; if these heterogeneous supervision signals are folded into contrastive learning without a common format, near-duplicate sources or targets across tasks become in-batch false negatives.
    • Mechanism. Every example is expressed as zi=(Ii, qi, ci, 𝒩i, yi): instruction, source, positive target, optional hard-negative set, optional graded relevance score. Each batch is drawn from a single dataset (keeping task definition consistent). Contrastive loss ℒCL is InfoNCE with a duplicate-aware mask Mi,j,c that zeros out any in-batch candidate whose source is near-duplicate to qi (s(qi,qj)>τdup) or whose target is near-duplicate to c+i; graded-relevance batches use a score-gap-weighted CoSENT-style ranking objective. Temperature τ is learnable.
    • Why it works / why it beats prior. The unified format lets task-specific batches be interleaved through the same multi-task pipeline without post-hoc reformatting per task, and the duplicate-aware mask is what prevents the shared-target-space collapse (e.g. classification datasets where many sources map to the same label). Prior MLLM-embedding pipelines (E5-V-style, MMRet-style, plain NV-Embed-vintage MLLM embedders) do not maintain a per-example mask that catches near-duplicates on both source and target sides.
  • Named contribution 2 — Semantic-ID-guided resampling for the curated stage.
    • Problem. The large-scale collection covers broad domains but its semantic distribution is skewed toward frequent patterns; retraining on it directly over-samples the head of the distribution and starves rare-but-informative semantic regions.
    • Mechanism. Semantic IDs (three-level residual k-means quantizer on intermediate-checkpoint embeddings) are derived per source–target pair. Assignment density at each codebook level is used as a resampling weight: pairs mapped to densely populated codes are down-sampled, pairs mapped to sparsely populated codes are retained at higher rates. The result is a curated corpus about 1/10 the raw size with improved semantic balance. An MLLM filter refines textual descriptions and drops mismatched pairs; hard negatives are synthesized (LLM-generated for text targets; intermediate-checkpoint retrieval for image and video targets), and a reranker assigns fine-grained relevance scores on a smaller subset.
    • Why it works / why it beats prior. A three-level RQ-KMeans code captures nested semantic structure without collapsing to a single flat cluster; using code density as a resampling signal without enforcing full uniformity avoids overshooting the rare tail. Uniform-sampling and IDF-style reweighting baselines do not condition on multi-level codebook density, so they either flatten the distribution too aggressively or preserve the head skew.
  • Named contribution 3 — two-stage training with Matryoshka Representation Learning, reranker supervision, and cross-scale embedding distillation.
    • Problem. A single embedding size fits some downstream constraints and not others (retrieval indexes at different byte budgets, on-device inference); training separate models per size wastes compute. A single-stage recipe cannot simultaneously give broad multi-task alignment and fine-grained relevance on hard negatives; a small model trained in isolation cannot inherit the discrimination structure of a larger sibling.
    • Mechanism. Input encoding appends a dedicated <embedding> token whose final-layer hidden state (L2-normalized) is the output representation; multiple <embedding> tokens can be inserted (e.g. one after video, one at end for video-only and joint video-text representations in a single forward pass). MRL supports flexible dimensions from a single training run by retaining the first d dimensions and renormalising, with predefined supported dimensions 𝒟MRL. Stage 1 trains on several hundred million pairs with InfoNCE plus CoSENT for graded relevance. Stage 2 fine-tunes on the curated corpus with graded relevance and hard negatives, adds reranker supervision (fine-grained ordinal scoring on a subset), and applies cross-scale embedding distillation from the 9B teacher into the 2B/4B students.
    • Why it works / why it beats prior. MRL delivers all supported dimensions from one forward pass, avoiding per-dimension retraining. Splitting alignment and refinement across two stages matches the pattern that yielded the largest gains in prior embedding-scale reports (E5, BGE, mmE5); adding reranker supervision on top of contrastive gives the model an ordinal signal contrastive-only training cannot express. Cross-scale distillation is what lets the 2B variant already surpass the previously leading 8B open baseline — the 2B student inherits discrimination structure from the 9B teacher rather than re-learning it end-to-end.

Evaluation & results

  • MMEB-v2 overall score (official leaderboard status as of 2026-08-24): WeMM-Embedding-9B = 80.6, ranking first ahead of all listed open-source and proprietary models; the compact 2B variant already surpasses the previously leading 8B open-source baseline.
  • Cross-modal retrieval suite (12-dataset, from Gemini Embedding 2 report): the 2B model compares favorably with leading proprietary models.
  • Text and agent-centric tasks: Section 4.1.2 reports text-retrieval and agent-centric downstream numbers alongside the general multimodal representation numbers.
  • In-house evaluation: substantial gains on a 26-task in-house benchmark spanning WeChat product surfaces.
  • Online A/B: consistent improvements across 14 online A/B tests; deployed at scale across WeChat Channels, Official Accounts, Moments, and e-commerce services.

Ablations

  • MRL analysis (Section 4.4.1): dimensions supported by MRL retain performance under prefix truncation and re-normalization; a single training run yields all supported sizes without a large gap to per-dimension retraining.
  • Stage-1 design analysis (Section 4.4.2): studies of contribution from unified pair-based format, duplicate-aware masking, and CoSENT-style ranking on graded pairs.
  • Cumulative Stage-2 analysis (Section 4.4.3): incremental contribution of Semantic-ID-guided resampling, MLLM quality refinement, hard-negative construction, reranker supervision, and cross-scale distillation, layered one at a time onto the Stage-1 checkpoint.
