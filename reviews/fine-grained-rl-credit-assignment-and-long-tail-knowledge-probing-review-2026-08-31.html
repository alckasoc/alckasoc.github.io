Rubric-to-Code Credit Assignment for Reinforcement Learning

Tier 2 · Research Paper arXiv 2026-08-28 Post-training · RL · GRPO · Credit assignment · Code generation · Web apps

Overview

  • Rui Jin, Jikai Chen, Yihan Chen, Hao Zhou, Demin Zhu, Kaichen Yang, Dong Wang, Chenyi Zhuang — Ant Group (the Ling / BaiLing model family). arXiv:2608.27906v1 [cs.AI], submitted 2026-08-28.
  • The framing: interactive web-application generation is not conventional code completion. A single natural-language request expands into many user-facing functional requirements (a Save button that writes to localStorage, a filter that hides completed rows, a modal that closes on Escape), and each requirement is realized by a localized region of the emitted HTML/CSS/JS — a specific event handler, a specific state update, a specific DOM fragment, a specific CSS selector. Standard GRPO collapses per-rubric functional pass/fail into a single sequence-level scalar and applies the same advantage uniformly to every generated token, so a broken Save-button handler and a correct modal share the same signal. Credit assignment collapses.
  • The paper introduces Rubric-to-Code Credit Assignment (RCCA): a rubric-first training pipeline plus a hierarchical reward that decomposes failures into format → source-code → runtime → functional strata, plus an evaluator-side attribution step that aligns each rubric’s pass/fail text to the responsible code span and its generated tokens. Trained on Ant Group’s Ling-3.0-Flash, the resulting Ling-RCCA-Flash reaches 41.25 on MiniAppBench (a +32.20-point lift over the base model, slightly above Claude Opus 4.5) and 76.19 on ArtifactsBench, +3.64 above the prior top-of-leaderboard GPT-5.

Methodology

  • Named contribution 1 — Rubric-first task construction.
    • Problem. RL over open-ended web-app generation needs a reward, but a scalar “does the app work” label is either binary and sparse (most partially-correct rollouts get 0) or an LLM-judge score that hides which specific piece failed. Neither exposes what a policy-gradient update should credit.
    • Mechanism. Each training task is built around an explicit list of user-facing functional rubrics (e.g., “clicking Save persists the current list to localStorage”, “empty-input Add is rejected with an inline error”). At rollout time, the generated HTML/CSS/JS is executed and each rubric is checked independently, producing a per-rubric pass/fail vector rather than a single number. The scalar reward the policy sees at the trajectory level is a weighted aggregate of the rubric outcomes; the per-rubric outcomes are kept for the localized credit step below.
    • Why it works / why it beats prior. Prior code-RL work (e.g., unit-test-driven GRPO on competitive-programming problems, or ArtifactsBench-style LLM-judge RL) either scores whole programs against opaque tests or collapses judge critique into one number. Explicit rubrics turn functional quality into an ordered, per-requirement label that can then be routed to specific code spans — the prerequisite for the localized credit signal.
  • Named contribution 2 — Hierarchical reward: format → source-code → runtime → functional.
    • Problem. If a rollout crashes at the parse stage, the model doesn’t need a functional-behavior signal — it needs to learn to emit parseable code first. Mixing all failure modes into a single scalar makes the earliest-stage errors (format, syntax) share bandwidth with the latest-stage ones (rubric-specific behavior), so the gradient wastes capacity chasing subtle rubric misses in trajectories that don’t even parse.
    • Mechanism. Rewards are staged: (i) format reward penalizes malformed tags / missing sections; (ii) source-code reward penalizes syntax errors caught before execution; (iii) runtime reward penalizes uncaught exceptions during headless-browser execution; (iv) functional reward is the per-rubric outcome vector from the rubric-check pipeline. Lower stages gate the higher ones: a format failure zeros the source-code / runtime / functional contributions for that rollout.
    • Why it works / why it beats prior. Stage-gating focuses the update on the earliest failure mode, so the policy learns to clear each stage before receiving signal from the next — the same reason curriculum RL beats flat-reward RL on multi-stage tasks. Baseline GRPO with a single ArtifactsBench-judge scalar shares bandwidth across all stages; the ablation section reports the hierarchical variant is what unlocks the ArtifactsBench gains over the SFT baseline (+4.48).
  • Named contribution 3 — Attribution alignment: rubric text → responsible code spans → generated tokens.
    • Problem. Even with per-rubric outcomes, standard GRPO still spreads each rubric’s advantage uniformly over every token in the trajectory. A failed Save-button rubric shouldn’t upweight or downweight tokens inside an unrelated CSS block; but without a mechanism to say which tokens implement Save, the signal is diluted.
    • Mechanism. For each rubric, an evaluator LLM produces a textual attribution — a short paragraph identifying the code region responsible for that rubric’s pass/fail. RCCA aligns that attribution back to concrete character spans in the generated file (event handler, selector, function body), then to the token indices those spans occupy in the rollout. The rubric’s scalar reward becomes a token-level advantage that is non-zero only on those aligned tokens; other tokens keep the trajectory-level baseline. Optimization proceeds as GRPO with this localized advantage.
    • Why it works / why it beats prior. Prior localized-credit approaches for code (e.g., token-level PPO with sparse execution rewards) rely on program traces to attribute credit and only cover code that actually executed. Attribution alignment goes through the rubric, so it credits code whose presence mattered (a missing event handler is diagnosable even though no tokens executed). The result is a signal that pushes the specific tokens that made a specific requirement pass or fail, exactly what the token-uniform-advantage baseline in GRPO discards.

The scale of the gain tracks the paper’s core claim: functional rubrics are what standard RL leaves on the table.
  • ArtifactsBench (official leaderboard setting, LLM-judge on artifact quality): 76.19, a +4.48-point lift over the SFT-only variant (71.71) and +3.64 above GPT-5’s prior top score (72.55). Ablations

  • The paper attributes the ArtifactsBench +4.48 gain over the SFT baseline to the token-localized attribution step; removing it and using a rubric-averaged scalar advantage collapses the gain back toward the SFT baseline. This is the mechanism-level check for the “attribution alignment” contribution.
  • Removing the hierarchical reward staging (single flat aggregate reward over format+syntax+runtime+function) degrades MiniAppBench substantially, matching the failure mode the hierarchy is designed to prevent: early-stage errors and late-stage rubric misses fight for the same gradient bandwidth.

ContextPilot: Teaching Agents for Proactive Context Management via Fine-grained RL

Tier 2 · Research Paper arXiv 2026-08-28 Post-training · RL · GRPO · Agentic context management · Long-horizon reasoning · EMNLP 2026

Overview

  • Zhuoshi Pan, Qizhi Pei, Junru Lu, Honglin Lin, H. Vicky Zhao, Di Yin, Xing Sun — Tsinghua University, Tencent Youtu Lab, Shanghai AI Lab. Corresponding authors: H. Vicky Zhao, Xing Sun. arXiv:2608.28476v1 [cs.CL], submitted 2026-08-28. Accepted to EMNLP 2026 Main Track. Code, model, and project at tencent.github.io/ContextPilot.
  • The framing: long-horizon ReAct-style agents accumulate every reasoning step, tool call, and tool response into a monotonically growing context. Passive management (rule-based truncation or summarization) can’t adapt across scenarios; proactive management — letting the model itself decide when and how to edit its context via tools — is more flexible but still bottlenecked by three specific limitations: (i) the standard proactive toolset is only search, delete, summarize, missing planning, long-term memory, and adaptive compression; (ii) RL fine-tuning of context-editing behavior treats every context-editing action as equally worth exploring, even though different tools cause very different downstream success variance; (iii) the trajectory-level reward is copy-pasted onto every intermediate context-editing snapshot regardless of that snapshot’s actual downstream value.
  • ContextPilot ships three named contributions matching those three limitations: an extended toolset (planning, long-term structured memory, soft context offloading), context-aware partial rollout that allocates the sampling budget to the highest-sensitivity context-editing actions, and fine-grained snapshot-level credit assignment that scores each intermediate snapshot by the mean reward of its downstream branches instead of the terminal trajectory’s reward.

Methodology

  • Named contribution 1 — Extended context-management toolset.
    • Problem. Existing proactive managers (Sculptor, StateLM, MemAct) equip the agent with a narrow set of edit primitives: searchContext, deleteContext, summarizeContext. That’s enough to shrink the context but not enough to organize it: agents can’t plan globally before acting, can’t maintain structured entity-event memory across scattered fragments, and can’t offload history in a form they can search later.
    • Mechanism. The toolset is extended along four axes on top of StateLM’s base tools: (i) Perception & Planning — analyzeText, checkBudget, plan; (ii) Information Retrieval — buildIndex, searchContext, readChunk, readMultiChunks; (iii) Memory Management — note, updateNote, readNote, plus new memorize / updateMemory / readMemory that extract structured entities, timestamps, and event episodes with edges between related items (readMemory returns the target memory and its graph neighbors); (iv) Context Offloading — deleteContext, summarizeContext, plus new compressContext (LLMLingua-2 lightweight compression) and foldHistory (discards all history, replaces it with a searchable keyword index that searchContext can query back later). memorize, updateMemory, and the offloading tools count as “context-editing” and segment the trajectory into snapshots at their invocation.
    • Why it works / why it beats prior. Search + delete + summarize alone can shrink but not reorganize. The added planning tools let the agent commit to a strategy before spending its budget; the graph-structured memory lets multi-fragment reasoning happen against a persistent object rather than repeated re-reads; foldHistory is a reversible compression — keywords survive so the agent can pull details back on demand — where prior deleteContext is destructive. Ablation Section 5.4 (“Tool design”) reports removing any of the three new categories degrades average score on long-context QA.
  • Named contribution 2 — Context-aware partial rollout for sensitivity-weighted exploration.
    • Problem. Trajectory-level GRPO samples N full rollouts uniformly across all decision points, but the pilot study (Fig. 2, Qwen3-8B on NovelQA) shows different context-management tools produce wildly different downstream success-rate variance. Uniform rollouts under-explore the highest-leverage decisions.
    • Mechanism. For each context-management action acmt, compute a sensitivity score 𝒮(acmt) = α ⋅ ΔCcmt + β ⋅ ΔHcmt, where ΔCcmt is the fractional context-length change caused by the action and ΔHcmt is the change in the average per-token entropy of the k tokens generated after the resulting observation, relative to the entropy of the first k tokens of the trajectory (the initial-query state, not the previous step — because the goal is to detect uncertainty shifts induced by tool use, not local wiggle). Budget: N=128 snapshots per query, seeded by 8 trajectory-level rollouts that yield up to M=64 snapshots; the remaining N−M snapshots are drawn by re-sampling continuations starting from the parent nodes of the top-sensitivity-scored context-management actions in the trajectory-level rollouts.
    • Why it works / why it beats prior. ARPO-style partial rollout, from which ContextPilot inherits the idea, allocates extra exploration to high-entropy tokens. ContextPilot adapts it specifically for context management: context-length change is a domain-appropriate proxy for “how much this action rewrote the state,” and initial-entropy reference (rather than adjacent-step) singles out actions that produce big uncertainty jumps from the initial query. The uniform-rollout baseline in the ablation section — “RL training design” — underperforms exactly on the hardest long-context QA queries where the model needs to branch differently after big context-edit events.
  • Named contribution 3 — Fine-grained snapshot-level credit assignment.
    • Problem. Prior snapshot-based training (Sculptor, StateLM) sets the reward of every intermediate snapshot equal to the terminal trajectory’s reward. A correct final answer credits every intermediate context-edit that led to it, including the redundant retrievals; a wrong final answer punishes every intermediate context-edit including the reasonable ones. The pilot case study (Fig. 3, StateLM-8B on BrowseComp+) shows correct answers routinely come from “weak” context-management chains and wrong ones from disciplined chains — so trajectory-level rewards reinforce the wrong behaviour.
    • Mechanism. Trajectory reward for a terminal snapshot: R(SM) = Rout + Rfmt + Rpen (outcome vs. ground truth, format parseability, penalties for invalid tool calls and context-length overruns). Intermediate snapshot reward: R(Si) = (1/|𝒯(Si)|) ΣT∈𝒯(Si) R(T), averaging over the set of terminal trajectories that pass through Si. Advantages are then group-normalized within all snapshots for the same query (𝒢={S(j)t}) and plugged into the GRPO objective, each snapshot treated as an independent sample. Appendix A provides the variance-reduction argument.
    • Why it works / why it beats prior. The mean-of-descendants estimator is a Monte-Carlo value estimate of the intermediate snapshot — unbiased in the limit and lower-variance than the copy-the-terminal-reward baseline whenever different branches disagree. Combined with sensitivity-weighted partial rollout, the high-sensitivity snapshots get more descendants and therefore lower-variance value estimates. This is what lets the trajectory-branching evidence in the pilot study (Fig. 2) actually feed the policy gradient.

Evaluation & Results

  • Base models: Qwen3-8B, Qwen3-14B, Gemma4-E4B-it (long-context QA); WebSailor-7B, WebExplorer-8B (deep search). SFT data: PublicDomain split of NovelQA + NarrativeQA train; RL data: LongBench-v2 train (QA) / 1K OpenSeeker samples (deep search). Training framework: verl.
  • Long-context QA benchmarks: NovelQA (Copyright split), ∞Bench En.MC, LongMemEval-S, BrowseComp+. Deep search: GAIA text-only (103 examples), BrowseComp, BrowseComp-ZH, xBench-DeepSearch. Multiple-choice benchmarks use exact match; the rest use LLM-as-a-Judge.
  • Reference results from the paper’s Table 2 (long-context QA, prior work rows carried from the StateLM paper): Qwen3.5-397B-A17B (no tools) scores 80.55 average across the four benchmarks; the same model with the ContextPilot toolset prompt-only reaches 87.16. Prior smaller RL-trained agents: RL-MemoryAgent-7B (60.24 / 62.45 / 40.60 on NovelQA / ∞Bench / LongMemEval-S), RL-MemoryAgent-14B (78.86 / 74.24 / 59.00), ReadAgent-8B (16.38 / 24.02 / 0.00). ContextPilot rows on Qwen3-8B / Qwen3-14B / Gemma4-E4B-it consistently outperform StateLM on the same base with a more compact working context (per the paper’s claim; full numbers in Table 2/3 in the arXiv PDF).
  • Deep search: ContextPilot on WebSailor-7B and WebExplorer-8B beats ReSum and SUPO on GAIA, BrowseComp, BrowseComp-ZH, and xBench-DeepSearch. The “stronger performance with a more compact working context” framing is the paper’s consistent finding across both task families.
  • Rollout budget at RL: N=128 snapshots per query, seeded by 8 trajectory rollouts giving up to M=64 snapshots; partial rollouts fill the remaining budget. Trajectories are capped at 8 snapshots. Inference limits: 30K input, 2K generation.

Ablations

  • Tool design ablation. Removing the newly-introduced planning, long-term memory, or soft-offloading tool categories individually each degrades average score, confirming that search+delete+summarize alone is insufficient for the harder benchmarks.
  • RL training design ablation. Removing context-aware partial rollout (uniform trajectory-level rollouts only) or removing fine-grained snapshot credit assignment (trajectory reward copied to intermediate snapshots) each degrades performance; both together underperform ContextPilot by a larger margin than either alone. Appendix H reports additional RL ablation.
  • Token efficiency. ContextPilot achieves the stronger scores with a smaller average working-context footprint than baselines; the token-efficiency analysis (Section 5.3) shows RL reshapes tool-use strategy toward earlier compression and more selective retrieval, and that improved tool-use correctness and task success rise together.

Blind Men and the Elephant: Probing the Epistemic Myopia of LLMs under Long-Tail Divergent Knowledge

Tier 2 · Research Paper arXiv 2026-08-28 Evaluation · Benchmark · Closed-book QA · Long-tail knowledge · Epistemic recall

Overview

  • Zhuoshi Pan, Junru Lu, Yan Qian, H. Vicky Zhao, Di Yin, Xing Sun — Tsinghua University, Tencent Youtu Lab. Same corresponding-author pair (Di Yin, Xing Sun) and lead author (Zhuoshi Pan) as ContextPilot. arXiv:2608.28478v1 [cs.CL], submitted 2026-08-28. 10 pages, 10 figures, 1 table, under review.
  • The framing: factual-QA benchmarks assume every question has one canonical answer, so a model that recalls one plausible account looks “correct” even when the training corpus contained multiple divergent accounts and the model quietly dropped the others. That single-answer framing obscures whether LLMs actually retain the divergent long-tail knowledge or silently converge to the dominant account. The paper introduces ElephantBench, a closed-book knowledge probe of 1,094 questions where the ground-truth answer is a set of accounts recovered from a low-exposure web corpus.
  • Headline finding across 32 models: the strongest model recovers both divergent accounts on only 52.4% of questions, and on nearly all of the remaining questions recalls one account but omits the other — a specific failure mode the paper calls “epistemic myopia.” Scaling parameters and inference-time reasoning improves per-account recall but does not close the gap to complete recall.

Methodology

  • Named contribution 1 — Graph-based auditable benchmark construction pipeline.
    • Problem. Handwriting divergent-account questions from scratch is unscalable, and mining web QA sites biases toward high-exposure canonical facts. The evaluator also needs to prove that the multi-account structure is real, not an artifact of scraping.
    • Mechanism. The pipeline (i) retrieves related documents from a low-exposure web corpus (limiting the odds any single source dominates); (ii) constructs a knowledge graph over the entities and claims in the retrieved documents and identifies naturally occurring disagreements — nodes where multiple source documents assert incompatible values for the same relation; (iii) converts each disagreement into a multi-account QA record whose answer is the set of asserted values, each paired with its originating source; (iv) verifies every candidate answer against its originating document and additional authoritative public sources; (v) sends the surviving records to human annotators for review. The result is 1,094 questions with a full source-provenance trail per answer — the “auditable” property.
    • Why it works / why it beats prior. Prior long-tail knowledge benchmarks (PopQA, EntityQuestions, LongFact) surface rare-but-canonical facts and score models on a single answer. ElephantBench is the first that operationalizes divergence itself as the target: a model can get a question “partially right” on it, and the grading metric distinguishes single-account recall from complete divergent-account recall. Because the pipeline is graph-driven and source-anchored, questions can be added cheaply as new disagreements are discovered in the corpus, and any grader dispute can be re-litigated against the recorded source documents.
  • Named contribution 2 — Multi-account recall metric and 32-model evaluation.
    • Problem. Standard exact-match / F1 metrics reward returning the dominant account and ignore the other. The evaluation needs to separately measure single-account recall (does the model know anything?) from complete-account recall (does it know both / all?).
    • Mechanism. Grading is closed-book: no retrieval, no tools, prompts elicit “list all accounts” answers, and each response is scored per-account against the source-verified set. Reported metrics separate (a) any-account recall from (b) complete-set recall. The paper runs the probe across 32 open- and closed-weight LLMs spanning parameter sizes and inference-time reasoning budgets, and also runs corpus-side analysis correlating each account’s exposure count in the pretraining-scale web corpus with the model’s recall of that account.
    • Why it works / why it beats prior. The two-recall decomposition is the mechanism that reveals epistemic myopia: without it, the same 52.4% complete-recall model looks fine on any single-answer benchmark. Cross-model, cross-scale evaluation makes the failure a structural claim rather than a model-specific fluke.

Evaluation & Results

  • Benchmark size: 1,094 questions, each with 2 or more distinct source-verified accounts, drawn from a low-exposure web corpus with human annotator review.
  • Coverage: 32 LLMs evaluated, spanning open- and closed-weight, parameter scales, and inference-time reasoning modes.
  • Headline number: the strongest evaluated model reaches only 52.4% complete divergent-account recall. On “nearly all remaining questions” the same model recalls one account but omits the other — the epistemic-myopia failure mode. Any-account recall is substantially higher than complete-account recall across every model tested.
  • Scaling analysis: increasing model size and inference-time reasoning budget both improve any-account recall and complete recall, but the gap persists at the largest / most-reasoning-capable frontier models. The paper’s reading: parametric memory converges toward the dominant account rather than storing both.
  • Corpus-exposure analysis: complete recall correlates positively with the exposure count of the minority-side account in the pretraining-scale corpus. Where the minority account appears more often (still less than the dominant), the model retains both; where minority exposure collapses, the model drops the minority even when the majority-side signal is strong.

Other

  • The paper positions ElephantBench as a reproducible probe for diagnosing epistemic myopia in parametric memory, and the graph-based pipeline as a scalable recipe to turn any long-tail corpus into source-traceable knowledge probes without hand-writing questions.
