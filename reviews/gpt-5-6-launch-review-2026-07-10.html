Architecture & capability tiers

Three tiers, one generation — the routing rationale.

  • Problem. A single flagship model forces every deployment into the same price/latency/capability bucket, so teams either overpay for routine calls or under-provision for hard ones. OpenAI’s prior GPT-5 numbered releases stacked improvements onto one central model tier, so cost-sensitive workloads (routing, classification, extraction, agent subtasks) had to be routed to older generations that missed the newest capability jumps.
  • Mechanism. GPT-5.6 splits the family into three same-generation tiers with the same 1.05M-context window and same Feb 16 2026 cutoff but distinct capability targets. Sol is trained to be the peak-capability model; Terra is trained explicitly as a GPT-5.5-competitive lower-cost model at $2.50 / $15 per 1M tokens; Luna is the highest-throughput, lowest-cost model at $1 / $6, tuned for routing, classification, extraction, and agent subtasks. The tiers are exposed as first-class API model IDs, not as reasoning-effort settings on one model.
  • Why. Product economics beat monolithic model choice: an ecosystem where teams can send routine work to Luna, high-quality production work to Terra, and escalations to Sol is cheaper end-to-end than routing everything through the flagship. The naming (generation number + durable tier name) means Sol / Terra / Luna can each advance on their own cadence without renumbering the family. Terra beats Fable 5 at ∼1/16 the cost on Agents’ Last Exam per OpenAI’s launch chart; Luna at $1 / $6 gives the volume tier real capability without dropping to GPT-5.5.

max reasoning effort — single-agent depth beyond xhigh.

  • Problem. Reasoning-effort ladders in earlier GPT models topped out at xhigh, which forced a hard cap on how long a single agent could think about one problem. For research synthesis, security triage, and multi-step engineering, correctness scales with search depth and self-check budget, and a single-agent cap leaves free-lunch quality on the table.
  • Mechanism. max is a new setting above xhigh in the ladder that gives the model more time to reason, explore alternatives, run checks, and revise its approach on one problem before emitting an answer. It is available to all users with GPT-5.6 access in ChatGPT Work and Codex, gated on toggle in settings. In the API it is the highest effort level for Sol / Terra / Luna, and it stacks with ultra.
  • Why. Deepening a single agent along one search path is a different lever than parallelizing across agents. max targets tasks where the answer requires many self-checks against a single chain of reasoning; parallel agents would waste tokens exploring redundant branches. On Terminal-Bench 2.1 Sol at max reaches 88.8%; Terra at max reaches 87.4%. The delta from xhigh to max is small on easy tasks and grows on hard ones, which is why max is off by default and opt-in per request.

ultra mode — the multi-agent reconciliation loop.

  • Problem. Single-agent reasoning at max can go arbitrarily deep on one search path, but frontier tasks (hard code migrations, long-horizon browsing, security-triage rollups) benefit from parallel exploration — different agents catching different failure modes and reconciling. Traditional self-consistency approaches (best-of-N sampling) require a downstream reranker and don’t let the sub-agents actually coordinate.
  • Mechanism. ultra is a mode — not just an effort level — that decomposes the task and spawns four subagents in parallel by default (with a 16-agent variant for BrowseComp and SEC-Bench Pro), lets each work on a component, then reconciles their outputs into a final answer. Reported latency is from the root agent; API cost and output-token totals bill all subagents. Available on Sol in ChatGPT Work (Pro/Enterprise) and Codex (Plus and higher), with an equivalent multi-agent beta in the Responses API for developers.
  • Why. The launch charts show ultra shifts the score-latency Pareto up and to the left across BrowseComp, SEC-Bench Pro, and Terminal-Bench 2.1: adding parallel agents reaches stronger results in less wall-clock time than a single agent at max. Concretely: Sol at max lands 88.8% Terminal-Bench 2.1; Sol Ultra hits 91.9% (+3.1 points) purely from parallelization. BrowseComp goes 90.4% → 92.2%; SEC-Bench Pro 71.2% → 74.3%. Trade-off is honest — each subagent bills tokens independently, so a single Ultra call can burn 4× or 16× the tokens of a single Sol call.

Programmatic Tool Calling — JavaScript in an isolated V8 runtime.

  • Problem. Standard function calling round-trips every tool result through the model, which is expensive when a task is deterministic tool orchestration on top of a large intermediate result set — e.g. fetch 500 records, filter to a subset, compute a derived value, then reason about it. Every step through the chat channel costs input tokens, output tokens, and a full inference call.
  • Mechanism. In the Responses API, GPT-5.6 can write a small program in JavaScript, run it inside an isolated V8 runtime provided by OpenAI, call eligible tools in parallel from the program (including loops and conditionals), retain intermediate results in the hosted runtime, and only return the reduced result to the model. The runtime has no package install, no direct network beyond the tools, no filesystem, no subprocesses, and no persistent state across requests; it is ZDR-compatible.
  • Why. Deterministic tool orchestration doesn’t need model intelligence per step; it needs the model to write the orchestration once, then a runtime that executes it. Doing the reduce in-runtime rather than through the model saves prompt tokens on the intermediate data and cuts model round-trips. Customer quotes on the launch page report 63.5% fewer tokens for Unity scene construction (PlayCo), 38% fewer prompt tokens for multi-step legal document analysis at no quality loss (Clio), and 24% fewer output tokens plus 28% faster completion on financial research (Rogo).

Predictable prompt caching.

  • Problem. Prior OpenAI prompt caching was implicit and best-effort — developers couldn’t reliably predict which prefix would be cached, how long, or how much the cache would save.
  • Mechanism. GPT-5.6 introduces explicit cache breakpoints (developers mark cache boundaries in the prompt), a guaranteed 30-minute minimum cache life, cached reads at a 90% discount off input pricing, and cached writes billed at 1.25× the uncached input rate as a new pricing line. Both input and output token pricing remain per 1M tokens per tier.
  • Why. Explicit breakpoints let developers align cached prefixes with their own prompt structure (system prompt + tool descriptions + few-shot examples cached; user turn variable), and predictable cache life makes serving math tractable for cost-sensitive workflows.

Safety & limitations

  • Preparedness classification. Sol does not cross OpenAI’s Cyber Critical threshold. In Chromium and Firefox evaluations, Sol identifies bugs and exploitation primitives but does not autonomously produce a functional full-chain exploit under tested conditions. Biology similarly stays below the Critical threshold: Sol can support legitimate research but does not provide end-to-end capability to create, engineer, or synthesize a novel dangerous biological threat.
  • Layered safeguard stack. Model-level refusal training + real-time misuse classifiers (cyber and biology) that can pause generation for a larger reasoning-model reviewer + account-level review of flagged activity + differentiated access (Trusted Access for Cyber for verified defenders). OpenAI reports GPT-5.6 Sol cyber safeguards block roughly 10× more potentially harmful activity than earlier models.
  • Automated red-teaming. ∼700,000 A100e GPU hours dedicated to black-box automated red-teaming aimed at universal jailbreaks (attacks that work across many prompts, not one narrow setting), plus extensive human third-party red-teaming. Rapid-remediation process feeds new jailbreak findings into ongoing evaluations.
  • Trusted Access for Cyber. Individuals and organizations can verify identity and request access to relaxed cyber safeguards for defensive work (vulnerability triage/validation, malware analysis, detection engineering, patch validation). Members must enable Advanced Account Security with hardware-backed passkeys by September 1 to retain access to the most cyber-capable models; Yubico partnership for preferred passkey pricing.
  • Access controls in high-risk jurisdictions. OpenAI notes additional restrictions on high-risk entities and jurisdictions consistent with the broader Executive Order compliance regime.
  • Known trade-off. The stricter safeguards create friction for benign work; ChatGPT and Codex expose a “retry on a lower-capability model” option to keep dual-use tasks moving. Overblocking is explicitly acknowledged as a security risk of its own.

  • ChatGPT: Plus, Pro, Business, Enterprise access Sol through medium and higher reasoning effort. Pro and Enterprise can select Sol Pro for highest-quality results.
