Gemma 4 Technical Report

Tier 1 · Technical Report arXiv:2607.02770 2026-07-02 Open-weight flagship · Natively multimodal · MoE + dense · Thinking mode · Encoder-free · QAT · MTP

Overview

  • Authors: Gemma Team, Google DeepMind (~275 named contributors + 201 additional). Correspondence: gemma4report@gmail.com. License: Apache 2.0. Weights released; Hugging Face collection under google/.
  • Positioning: the fourth generation of the Gemma open family. Frames itself as an on-device / edge-focused open flagship that rivals larger open MoEs on Arena Text and posts frontier-level static-benchmark numbers in thinking mode, while shipping quantized checkpoints small enough to fit on mobile.
  • Five variants: E2B (2.3B effective / 5B total via per-layer embeddings), E4B (4.5B effective / 8B total), 12B dense unified encoder-free, 26B-A4B MoE (3.8B activated of 26B total), 31B dense. All decoder-only Transformers with pre-norm + post-norm RMSNorm and QKNorm; 262k SentencePiece vocab shared with Gemini.
  • Headline numbers (thinking mode): 31B posts MMLU-Pro 85.2, AIME 2026 no-tools 89.2, LiveCodeBench v6 80.0, Codeforces Elo 2150, GPQA Diamond 84.3, HLE 19.5 (26.5 with search), Big Bench Extra Hard 74.4. Arena Text Elo 1451 (rank 43), top open dense.

Architecture

Long-context efficiency — the p-RoPE + shared-KV design.

  • Problem. A 32k / 128k context with standard MHA blows up the KV cache at inference — Gemma 3’s local/global attention still spent most of the memory in the global layers, capping how big a context could actually be served on-device.
  • Mechanism. Three combined changes on the global layers only, keeping local sliding-window attention untouched. (1) Local-to-global ratio is 5:1 for all variants except E2B, which uses 4:1. (2) Positional encoding is p-RoPE with p=0.25 on global layers (only 25% of the RoPE frequencies are rotated); local layers keep standard RoPE. Global RoPE base is 1M, local is 10k. (3) In every global layer except E2B/E4B, keys are reused as values (values = keys), collapsing two KV projections into one and halving the global-layer V-cache. Combined with KV-cache sharing patterns of 20/35 (E2B) and 18/42 (E4B), the global KV footprint shrinks by 37.5%.
  • Why. Reusing keys as values at global layers is only viable because p-RoPE prevents aggressive rotation from destroying key/value coherence in the layers doing long-range retrieval; the 5:1 local-to-global ratio means the local (windowed) layers absorb most of the token count and only 1/6 of layers pay the global cost. The memory savings compound multiplicatively with layer count and context length — Gemma 3 27B needed ∼27 GB for 32k text with int8 KV cache, Gemma 4 31B fits the same context with a +1.10 GB KV addition on top of a 19.2 GB Q4_0 weight footprint.

Encoder-free 12B — ingest raw patches, drop the vision and audio encoders.

  • Problem. Standard multimodal Gemmas ship a 150M or 550M ViT and a 305M USM-based conformer audio encoder alongside the LLM. On device this means three separate weight blobs, three separate compilations, and memory fragmentation when swapping between modalities.
  • Mechanism. The 12B trains from scratch under a unified encoder-free paradigm. For vision, 48×48×3 RGB patches skip the ViT entirely and are lifted straight into the LLM embedding space by a single 35M-parameter matmul, with 2D coordinate-based positional embeddings + LayerNorm before the first Transformer block. For audio, the 305M USM conformer is discarded outright; raw 16 kHz waveform is segmented into 40 ms chunks (640-dim per chunk) and projected directly into the embedding space with no additional positional encoding because audio is already ordered temporally.
  • Why. A dedicated ViT-style encoder is a training-efficiency shortcut, not a correctness requirement — if the LLM is deep enough, it can absorb the “encoder” work into its own early layers. Eliminating the separate encoder collapses the memory graph (one weight blob, one compile), removes a source of mid-inference fragmentation, and still delivers competitive FLEURS ASR (WER 0.063 en, 0.038 es, 0.057 ko*) and CoVoST S2TT (BLEU 41.9 de→en, 44.6 es→en) without a dedicated audio encoder.

MTP drafter — speculative decoding with a per-model draft head.

  • Problem. Speculative decoding wants a lightweight draft model that shares its KV cache with the main model, but a naive linear draft head has to project into the full 262k vocabulary each step; on E2B / E4B that projection is a substantial fraction of decode latency.
  • Mechanism. The MTP head takes the main model’s last-layer activations and previous-step token embeddings, then runs a small 4-layer Transformer that cross-attends to the main model’s KVs. Model dimension is 256 for E2B/E4B and 1024 for 26B-A4B/31B; the block is 3 local + 1 global attention layer. There is no separate MTP prefill and any draft length is supported. For E2B/E4B the final vocabulary projection is replaced with a top-k over clusters of tokens: the matmul shrinks from d×262,000 to d×4096 while acceptance rate is preserved.
  • Why. The cross-attention design means the drafter reuses the main model’s KV cache directly (no draft-side KV rebuild), and the token-cluster top-k eliminates the vocab projection as the drafter bottleneck on the smallest models. Combined with QAT, this is what lets E2B fit in 0.8 GB of quantized weights and still run speculative decoding.

Pre-training

  • Data: web documents, code, images, and audio (only for E2B/E4B/12B). Data cutoff Jan 2025. Tokenizer inherited from Gemini — SentencePiece, 262k entries, split digits, preserved whitespace, byte-level fallback.
  • Compute: E2B on 4,096 TPU v6e chips, E4B on 6,144 v6e, 12B on 12,288 TPU v5p, 26B-A4B on 6,144 v6e, 31B on 10,240 v6e. All shard the optimizer state via ZeRO-3 and use GSPMD + MegaScale XLA; multi-pod jobs replica-reduce over the data-center network via Pathways.
  • Slice-Granularity Elasticity (Gemini-style) lets training keep running with fewer TPU slices under a localized failure, reducing interruption delay from minutes to seconds.

Quantization-Aware Training — two profiles.

  • Problem. Post-training quantization typically loses several points on MMLU-class benchmarks at <4-bit weights on Gemma-sized models; on-device deployment needs the small memory number and the eval number.
  • Mechanism. Two QAT profiles bake the quantization schedule into training. (1) Mobile quantization: per-channel weights at a mix of int2/int4 with int8 activations, targeting llama.cpp-style inference. (2) Q4_0: blockwise weight quantization. A scalar scale is added per block to bound activation ranges so fp16 inference stays stable. QAT is also applied to the image and audio encoders: on the 150M vision encoder, W8A8 gives 2× forward-pass memory reduction (400 MB → 200 MB) and 44% lower on-device latency vs. Gemma 3n; on the audio encoder, weights are quantized to a per-cluster mix of {2, 4, 8} bits and the audio encoder shrinks 78% on disk (390 MB → 87 MB).
  • Why. QAT preserves quality because gradients see the quantization noise during training; the per-block scalar bounds activations exactly at the range fp16 can represent, so downstream inference engines don’t drift. Result: E2B fits in 0.8 GB, E4B in 2.3 GB, 12B in 7.65 GB, 31B in 19.2 GB — a full 32k KV cache in int8 costs only +0.05, +0.14, +0.28, and +1.10 GB respectively on top of the weights.

DSpark: Confidence-Scheduled Speculative Decoding with Semi-Autoregressive Generation

Tier 2 · Research Paper arXiv:2607.05147 2026-07-06 Speculative decoding · Semi-autoregressive drafter · Confidence scheduling · DeepSeek-V4 serving

Overview

  • Authors: Xin Cheng, Xingkai Yu, Chenze Shao, Jiashi Li, et al., with Wenfeng Liang as corresponding — the DeepSeek team, deployed inside the production DeepSeek-V4 serving system.
  • Positioning: a serving-side speculative-decoding framework, not a new model. Two-part contribution: a semi-autoregressive drafter that mitigates the acceptance decay of parallel drafters, and a per-request confidence-scheduled verification pass that adapts verification length to survival probability and engine throughput.
  • Headline result: replacing MTP-1 as the production baseline inside DeepSeek-V4, DSpark accelerates per-user generation speeds by 60–85% at matched aggregate throughput levels, and enables interactivity tiers previously unreachable under strict latency SLOs.

Methodology

Semi-autoregressive drafter — a sequential module attached to a parallel backbone.

  • Problem. Parallel drafters (MTP-K, Medusa-style heads, Eagle-parallel) generate a whole block of K candidate tokens in a single forward pass, which is fast but breaks intra-block dependencies. Acceptance rate decays sharply along the block: the first token accepts often, later positions almost never, because each drafted position was produced independently of the ones before it.
  • Mechanism. DSpark keeps the parallel backbone that emits K positions in one pass but adds a lightweight sequential module on top that autoregressively refines those positions using the earlier positions as context. Concretely, position k is re-scored conditional on positions 1..k−1 that were sampled from the parallel head, and the sequential module’s cost is small enough that a K-token draft still costs one main-model forward pass in total. The verifier then applies standard rejection sampling over the sequential outputs.
  • Why. The parallel head gives the throughput of block generation; the sequential module puts back exactly the dependency that made autoregressive drafters (Eagle-1/2, Medusa-2) accept more tokens per verification. Net effect: acceptance rate profile flattens across positions in the block, so accepted-length improves without paying the latency of a fully autoregressive drafter.

Confidence-scheduled verification — load-aware per-request draft length.

  • Problem. In high-concurrency serving, verifying a fixed long draft for every request is wasteful: many requests reject early in the block, and the wasted verification steals batch capacity from other requests. Under strict interactivity SLOs (e.g. TPOT<30 ms), that waste collapses total throughput.
  • Mechanism. DSpark estimates, per request, the prefix survival probability at each position of the draft (probability that the draft is still accepted at step k) and combines it with an engine-specific throughput profile of “cost of one more verified position vs. gained accepted tokens.” The scheduler solves for the verification length K* that maximises expected accepted-tokens-per-batched-verification-slot given the current concurrency level. K* is chosen per request, per step, and adapts as load fluctuates.
  • Why. Fixed-K verification underuses capacity in low-load regimes and over-uses it in high-load regimes; a load-aware scheduler gets both. In production this is what preserves throughput under strict SLOs — DSpark holds a serviceable interactivity tier that MTP-1 collapses in.

Evaluation & results

  • Offline benchmarks across diverse domains show DSpark substantially improves the accepted length vs. state-of-the-art AR and parallel drafters (per-benchmark numbers in the paper).
  • Online: deployed inside DeepSeek-V4 serving under live user traffic against the MTP-1 production baseline. Per-user generation speed +60–85% at matched throughput.
  • The paper frames the online result as shifting the Pareto frontier of the serving system — strict TPOT SLOs that MTP-1 could not serve at any batch size become achievable under DSpark.

Ablations

  • Semi-autoregressive vs. pure parallel drafter: sequential module lifts accepted length; the paper attributes most of the acceptance gains to it, with the confidence scheduler contributing on the throughput axis instead.
  • Confidence scheduler vs. fixed K: fixed K sees increasing waste as concurrency grows; scheduled K holds accepted-tokens-per-slot approximately flat.

Nemotron-Labs-Diffusion: A Tri-Mode Language Model Unifying Autoregressive, Diffusion, and Self-Speculation Decoding

Tier 2 · Research Paper arXiv:2607.05722 2026-07-07 Diffusion LM · Joint AR-diffusion training · Self-speculation · GB200 SGLang

Overview

  • Authors: Yonggan Fu, Lexington Whalen, Abhinav Garg, Chengyue Wu, Enze Xie, Song Han, Jan Kautz, Pavlo Molchanov, et al. — NVIDIA Research.
  • Positioning: a single 3B/8B/14B backbone family (base, instruct, and vision-language) trained under a joint AR-diffusion objective, deployable in three decoding modes without swapping models. Directly competitive with AR LMs of matched size on quality and with diffusion LMs on speed.
  • Headline numbers: 8B decodes 6× more tokens per forward than Qwen3-8B at matched accuracy, translating to 4× SPEED-Bench throughput with SGLang on a GB200. Speed-of-light analysis: up to 76.5% more tokens per forward vs. self-speculation under an optimal sampler.

Methodology

Joint AR-diffusion training objective — complementary priors in one model.

  • Problem. Autoregressive LMs give clean left-to-right likelihoods and strong linguistic priors, but decoding is inherently sequential. Diffusion LMs can generate multiple tokens per forward pass and plan farther ahead, but training either objective alone forces you to pick a lane — a diffusion-only model loses AR’s linguistic sharpness, an AR-only model can’t use diffusion’s lookahead at inference.
  • Mechanism. Nemotron-Labs-Diffusion is trained with a joint objective that samples the AR loss and the (masked) diffusion loss on the same batches through the same backbone. Because the two losses share parameters, the network learns representations that support both a stepwise causal readout and a full-sequence denoising readout. At inference the same weights can be used as (1) AR: standard causal decode; (2) diffusion: iterative denoising of a masked sequence for lookahead planning; (3) self-speculation: diffusion drafts a block, AR verifies it against its own causal likelihood.
  • Why. This isolates the strength of each mode — AR’s left-to-right prior is exactly what you need to verify a draft cheaply; diffusion’s parallel readout is exactly what you need to produce the draft. Self-speculation mode outperforms MTP-K style multi-token prediction in both acceptance rate and real-device efficiency because the diffusion draft has richer intra-block dependency structure than a parallel head can capture.

Self-speculation decoding mode.

  • Problem. Standard speculative decoding needs a separate draft model, which duplicates parameters and complicates deployment. Multi-token prediction (MTP) heads share weights but fall back to parallel drafters’ acceptance decay.
  • Mechanism. The same backbone drafts by running one diffusion denoising step over a masked block, then verifies the draft against its own AR forward pass. Acceptance is decided position-by-position under the AR probabilities; rejected suffixes are truncated and re-drafted with a fresh mask.
  • Why. Because the drafter is the same weights as the verifier, there is no draft-model mismatch to bound acceptance. Diffusion-drafted tokens carry intra-block dependency structure that MTP-K parallel heads miss; on real hardware this compounds with the fewer forward passes needed to hit a target output length.

Evaluation & results

  • Scaling: 3B, 8B, 14B backbones with base, instruct, and vision-language variants; consistently outperforms open-source AR and diffusion LMs on both accuracy and speed axes.
  • Nemotron-Labs-Diffusion-8B: 6× more tokens per forward pass than Qwen3-8B at comparable accuracy; 4× higher throughput on SPEED-Bench with SGLang on a GB200 GPU.
  • Speed-of-light analysis: under an optimal sampler, diffusion decodes up to 76.5% more tokens per forward than the self-speculation configuration, suggesting the sampler is currently the dominant loss vs. theoretical throughput.

Ablations

  • AR-only vs. diffusion-only vs. joint: joint recovers AR’s left-to-right likelihood while retaining diffusion’s parallel readout. Diffusion-only loses ground on standard AR benchmarks; AR-only cannot exploit self-speculation.
  • Self-speculation vs. MTP-K: same backbone, same size. Self-speculation wins on both acceptance and real-device efficiency because MTP-K has no way to model intra-block dependencies with position-independent heads.

Hierarchical Sparse Attention Done Right: Toward Infinite Context Modeling

Tier 2 · Research Paper arXiv:2607.02980 2026-07-03 Sparse attention · Chunk selection · Length extrapolation · Continued pre-training

Overview

  • Authors: Xiang Hu, Xinyu Wei, Hao Gu, Minshen Zhang, Tian Liang, Huayang Li, et al. Frontier affiliation: Tencent HY Team (Hunyuan) — six of the authors, including the core contributors and corresponding author Leo Liang. Collaborators: ShanghaiTech, HKUST, UC San Diego. Code at github.com/Tencent-Hunyuan/HiLS-Attention.
  • Positioning: not a new model line — a drop-in attention replacement designed to be trainable from scratch and to convert full-attention models via lightweight continued pre-training. Directly targets NSA (Native Sparse Attention), MoBA (Mixture of Block Attention), and NOSA as the prior sparse-attention baselines it needs to beat.
  • Headline results: HiLS-Attention matches full attention at in-domain context lengths, extrapolates 64× the training context with 90% retrieval accuracy on needle-in-a-haystack, and reaches 512× extrapolation at the 345M-param scale (8K trained → 4M served). A 7B full-attention model converted with 50B continued-training tokens preserves short-context performance and beats the YaRN-extended full-attention baseline on LongBench.

Methodology

HiLS-Attention — the mechanism.

  • Problem. Existing chunk-wise sparse attention methods (NSA, MoBA, NOSA) all use non-parametric or weakly-parametric chunk summaries (mean pooling, cheap encoders) to score chunks for top-K selection. After the hard top-K pick, the retrieval scores are discarded: they never enter the forward attention weights. Consequently the LM loss cannot flow back through the retrieval decision, so chunk selection stays inaccurate and long-context recall degrades exactly where it matters — parameter-constrained models on precise in-context retrieval.
  • Mechanism. Two-part fix. (1) Each chunk gets a landmark token appended during training; the landmark’s key becomes the chunk’s summary key. The query-summary scoring operation is derived as the first-order Taylor expansion of full-attention-induced chunk mass, so the summary is provably aligned with what naive Block Sparse Attention would pick if you computed full attention and then summed token mass per chunk. (2) A hierarchical softmax factorises the attention. Each query attends independently within each of its K retrieved chunks to extract chunk-local information; the per-chunk outputs are then fused according to the softmax-normalised retrieval scores. Because those retrieval scores are part of the forward attention weights, they receive gradient from the LM loss directly — retrieval is trained end-to-end under the language-modeling objective.
  • Why. The landmark-derived summary carries enough parametric capacity to represent the full-attention chunk mass (that’s the Taylor-expansion argument), so top-K is accurate. The hierarchical softmax means the LM loss can promote chunks that help next-token prediction and suppress irrelevant chunks — the score is optimised, not just used. Beats NSA / MoBA / NOSA on retrieval accuracy at long context precisely because those methods can’t train their selector under LM loss.

Practical design.

  • Positional encoding: standard RoPE per token, plus a chunk-level positional offset consumed by the landmark scoring path so the summary keys carry chunk position.
  • Low-rank query calibration: a small low-rank projection on queries used only for the retrieval-score path, keeping the main attention path unchanged.
  • GQA integration: keys/values grouped as in GQA; the landmark key lives in the shared KV group so retrieval scores are shared across heads within a group, reducing memory.
  • Landmark-token-free alternative: for models where inserting a landmark token is inconvenient, a variant derives the summary from the last real token of each chunk with the same Taylor-alignment argument.
  • Hardware-efficient kernel: a fused kernel that streams the sparse KV loads for the selected chunks — the sparse KV access pattern is what turns algorithmic FLOP savings into wall-clock speedup.

Evaluation & results

  • Small-scale (345M): HiLS-Attention matches full attention on perplexity in-domain and beats it on RULER; trained at 8K context, needle-in-a-haystack accuracy stays above 90% at 4M served — 512× length extrapolation.
  • At 256K training context: on a challenging variable-tracking task, HiLS-Attention beats full attention by up to 50 points — the gap widens with context length, opposite to the usual sparse-attention regression.
  • 7B scale, continued pre-training: converting a full-attention 7B model with 50B tokens of continued training preserves short-context performance and surpasses the YaRN-extended full-attention baseline on LongBench.
  • Inference efficiency: sparse KV access means constant per-token cost as context grows — total inference latency at long context is bounded by the number of retrieved chunks, not the sequence length.

Ablations

  • Chunk overlap: overlapping chunks (each token belongs to two adjacent chunks) helps at chunk boundaries but is not required for the 90% retrieval accuracy result.
  • Landmark vs. landmark-free variant: landmark-free loses a small amount of retrieval accuracy but is easier to plug into pre-trained models.
  • Low-rank query calibration is what closes the last gap to full attention on short-context perplexity; removing it re-opens the gap.

Other

  • Related work section frames HiLS as the first chunk-wise sparse attention to demonstrate both stronger long-context performance and more efficient long-context inference than full attention — a stated departure from the usual efficiency-vs-quality trade-off.
  • Continued-training strategy is the practical upgrade path for existing full-attention models; only 50B tokens are needed to convert a 7B model, small relative to a full pre-training run.
